# 万达电影票 AI 客服

插件 ID：`wanda-seat-autoquote`  
开发者：`xdl`

用于万达电影票智能客服、截图识别、官方场次与实时座位核验、W+ 优惠探测、自动报价和待付款订单安全改价。会话智能体负责理解意图、连续追问和选择受控工具；价格、库存、订单与改价仍由确定性安全引擎裁决。插件不会自动付款、自动出票、发送票码、发货、催收货或评价。

## 使用步骤

1. 在“自动化设置”中同步店铺并开启目标店铺。
2. 配置报价调整值、自动报价和自动改价开关。
3. 在“回复文案”中确认首次提示、报价、下单、失败和付款文案。
4. 买家发送完整选座页截图并说明张数。
5. 插件识别影院、影片、日期、开场时间、影厅和官方已选座信息，然后通过官方影院库、万达实时场次和实时座位图核验。
6. 需要读取 W+ 最终优惠时，系统只在核价期间创建临时试价订单，立即取消并确认座位恢复；释放未确认时停止报价。
7. 买家接受完整报价后回复“确认”，按操作图提交订单并保持待付款。
8. 插件收到 `order.created` 后重新读取权威订单，全部门禁通过才改价；只有收到并核验 `order.price.changed` 后才提示付款。
9. 已付款订单只进入人工出票或异常处理，不再自动核价和改价。

## 报价与识别规则

- 最终金额只来自万达实时座位原价、临时试价订单 `available-offers` 中唯一可用的“W+会员专享优惠”和后台报价规则。
- 截图价格、买家文字价格、手绘标记和历史报价不参与金额计算。
- 当截图中存在高置信度且同座区、同张数的明确低价，而本店实时报价更高时，只提示买家可在当前 APP 自行购买，不绑定本店报价。
- 官方已选座必须逐座命中实时座位图；手绘圈选只作为人工出票位置偏好，不推断座位号。
- 城市可缺省，但影院必须通过官方影院、影片、绝对日期、开场时间和必要时影厅联合唯一匹配。
- 买家圈选图片保存为“按原图圈选位置出票”的履约指令，系统无需识别具体座位号；文字座位不冒充官方选座。

完整业务安全规则见项目根目录 `BUSINESS_RULES.md`。

## 会话智能体

后台支持三种模式：`off` 使用原受限回复；`shadow` 生成并记录结构化计划但不影响买家；`active` 允许智能体管理低风险对话和请求受控工具。智能体 action 采用严格白名单，不能生成 `change_price`、创建订单、付款、锁座、出票、退款或发货动作；模型提供的金额和订单执行参数会在插件与后端两层拒绝。影子Agent使用独立持久化worker和最多8步的有界 Observe → Plan → Tool → Observation 循环，每步保存检查点，使用独立60秒租约并每15秒续租，可在租约过期后恢复；每轮默认3分钟deadline，到期记录为`timed_out`并停止后续步骤。它不会阻塞买家业务事件。工具调用在执行前记录为`pending`，完成后持久化有界Observation；恢复时回放已完成结果，未知结果失败关闭且不重复调用。Active回复使用独立持久化outbox，以稳定action ID去重；独立单并发worker保留消息去重与人工接管门禁，成功后登记平台消息ID，发送结果未知时不盲目重发。运行时显式使用`execution_owner`，owner不是`agent`时即使遗留Active配置也自动降级为Shadow。`create_manual_task`使用租户隔离的持久化队列和事件派生任务ID；关联账号、会话、买家及订单只从系统上下文注入。开放任务显示在异常复核，可打开原会话并由认证后台标记完成；Shadow不会创建任务。服务停止时会中止正在等待的Agent模型请求并安全延后任务，避免systemd强杀。独立持久化Active Runner已支持保守白名单内的低风险流程咨询：业务事件只负责调度，Agent worker规划，安全回复经outbox发送；每次运行还会复核源事件`execution_owner=agent`。图片、核价、报价、订单和付款轮次继续由确定性链路处理。Agent Runtime已接入无参数`inspect_ticket_request`与`read_linked_order`：前者只输出有界票务请求事实，后者仅使用系统关联订单读取闲鱼权威状态，不向模型暴露订单号、买家或完整平台响应。Active工具失败或结果未知会幂等创建人工任务并经outbox发送安全提示。Active Runtime现已具备真实`recognize_image → resolve_showtime → quote_realtime`工具链。场次解析使用只读接口，不读座位、不锁座；只有实时核价进入既有临时试价和释放验证。跨工具artifact持久化但不发送给模型，工具完成结果可恢复，未知结果不重试；Shadow不会重复副作用核价。Agent权威报价现通过outbox两阶段提交：平台发送成功后先保存消息ID，再幂等提交总价、张数、规则版本、场次、成本及圈选原图到会话报价状态；本地提交失败只重试提交，不重发消息，发送未知或人工接管跳过不会形成有效报价。报价回复会附加确认指令，有效期从送达提交时开始。Active图片路由仍关闭，待端到端评测后再开放。闲鱼账号明确返回`E_IM_WS_UNAVAILABLE`时，事件改为每10秒短间隔保留重试约1小时；首次回复发送失败会释放占用，连接恢复后继续处理，不再指数退避数分钟或8次后永久失败。账号WS断线期间仍无法收发IM，需要先在鱼麦多后台恢复账号连接。后台新增低风险Active Canary门禁：只统计明确审计过高风险动作、虚假声明和重复追问的样本；至少100轮、工具正确率不低于95%，且三项风险与权威结果不一致均为0才显示通过。后台同时自动评估图片Shadow工具链：至少100轮、完成率和成功报价完整路径均不低于95%，实时核价重复调用、未知工具结果、高风险工具和权威结果不一致均为0，并展示P50/P95端到端时延。后台新增独立“人工介入对照监督”扫描器：非插件卖家回复会关联上一条买家问题、会话事实、报价/订单状态及对应Shadow计划，生成脱敏、幂等、待人工审核的对照草稿。自动比较意图、工具、事实、风险和回复策略，但不会直接训练模型或修改规则；审核后只能选择拟沉淀到知识库、回复模板、业务规则或工具门禁。扫描器与买家业务worker彻底解耦。为降低多步Agent延迟，图片首步、已有工具Observation的续步和明确的核价/张数/订单/付款/出票/售后等常见票务文字使用关闭深度思考、400 Token上限的快速规划；只有不命中明确票务意图的首次复杂纯文字咨询保留思考能力。快速规划不改变工具白名单和交易门禁。通过不会自动打开Active，仍需人工批准。Active仍由后端硬性拒绝，待评测达标后再分风险开放。识图、场次匹配和实时核价是独立受控工具，未知计划、低置信度、工具错误、人工接管或已付款状态均失败关闭。当前Runtime还对每个工具强制执行副作用、允许事实字段、下一步动作和权威回复契约；未声明输出以`agent_tool_contract_violation`失败关闭，持久化写工具在非Active模式执行前阻断。后台可脱敏回放每轮计划、工具journal、Observation和耗时；人工任务支持负责人、优先级、标签、SLA与内部备注。已审核回复知识按通用、接待资料、报价后追问、下单待付款、付款出票和售后场景有界注入，不能覆盖权威交易事实。

## 自动改价安全门禁

自动改价前必须同时满足：店铺与功能已启用、报价已真实送达并确认、报价未过期、场次唯一、数量一致、订单属于当前店铺、订单仍待付款、当前邮费受支持、目标金额与报价一致、金额不超过后台上限、没有人工接管。

`order.created` 可能早于平台上游订单写状态就绪。首次返回 `CANNOT_MODIFY_FEE` 时，插件仅在重新读取订单并重新通过全部门禁后做有界延迟重试；订单已付款、金额变化、报价过期或人工接管时立即停止。

## 后台页面

- **自动化设置**：店铺开关、报价规则和自动改价上限。
- **AI 设置**：文字回复模型、消息合并等待和人工接管保护。视觉识别由受控后端处理。
- **回复文案**：固定买家文案的唯一管理入口；新消息按当前模板原样发送。
- **报价记录**：展示已由权威实时核价形成的单价、合计、影院、阶段与会话入口，不保存截图标价或完整聊天。
- **订单管理**：汇总待付款、已付款、人工出票、售后和异常订单；人工按钮只回写已完成的出票状态，不发货、不发送票码、不改金额。
- **异常记录**：用于定位识别、核价、改价和发送失败；有关联会话时可跳转，纯订单后台事件只显示诊断，不展示不可点击的假按钮。

报价历史可以作为未来价格建议的训练样本，但只能使用影院、场次、实时成本、供需和成交结果等非个人因素。不得按买家身份、历史议价能力或支付意愿差别定价，也不得绕过成本下限、实时原价封顶、买家APP低价保护和订单安全门禁。

## 常见问题

### 为什么没有立即回复？

插件先等待短暂的连续消息合并窗口，再执行视觉识别和万达实时核价。普通识图与核价由持久化 worker 异步执行，不阻塞 5 秒 webhook ACK。万达接口慢、跨影院消歧或临时优惠探测会增加耗时。

### 为什么提示补充城市？

只有“万达广场 IMAX 店”等通用标题时无法唯一确定分店。回复城市即可继承原截图继续匹配，无需重发。

### 为什么提示先不要付款？

买家订单初始金额可能不是确认报价。只有系统真实改价成功并回读一致后才允许付款。

### 为什么改价转人工？

常见原因包括订单尚未写就绪、订单已付款、报价失效、金额或数量不一致、人工接管、平台授权失败或上游业务拒绝。后台“异常与记录”会展示脱敏诊断。

## 隐私与安全

- webhook 使用平台颁发的 secret 对原始 body 做 HMAC-SHA256 验签，并校验 ±300 秒时间窗。
- 长任务先加密持久入队再 ACK；同一事件和消息跨重投幂等。
- Token、Cookie、商家模型密钥、完整平台响应、买家完整消息和票码不写入运营日志。
- 商家模型密钥使用 AES-256-GCM 加密保存且不回显。
- 图片下载仅允许 HTTPS 白名单 CDN，拒绝私网地址、危险重定向和超大文件。
- 报价预览最多保留 24 小时、500 条；会话只保存业务所需的最小化状态。
- 历史Agent评测扫描完整持久化运行索引，不受运营列表500条上限影响；图片与文字各自最多补齐100轮，图片优先，但始终只保留一个历史评测任务在途。
- UI 通过鱼麦多 iframe SDK 和网关签名访问；生产环境不开放本地绕过。
