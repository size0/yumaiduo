# V2 架构边界

## 目标

V2采用“规则状态机、持久命令、插件执行器”的单向架构：

```text
鱼麦多事件
  -> 插件验签并持久接收
  -> 后端SQLite Inbox确认accepted
  -> 唯一规则状态机归约并写Command Outbox
  -> 插件以60秒租约领取命令
  -> 插件执行并官方回读
  -> 后端持久回执并再次归约
```

事件HTTP响应不返回动作；AI只返回候选，不能成为命令所有者。

面板图片识别等长任务先写入加密的持久任务目录，再返回 `202`；插件重启时会回收处理中租约并继续执行，禁止使用仅内存任务。

## 代码所有权

| 能力 | 所属 | 说明 |
| --- | --- | --- |
| 鱼麦多注册、验签、SDK client | 插件 | 仅平台接入 |
| 事件幂等、同会话串行、动作回执 | 插件 | 保障执行可靠性 |
| 发消息、改价、改价后回读 | 插件 | 仅执行后端批准的动作 |
| 事件Inbox、交易状态、迁移证据、命令Outbox | 后端 | SQLite WAL唯一运行库 |
| 图片理解、OCR、场次匹配 | 后端 | 模型输出不能直接成为事实 |
| 实时座位、锁座、活动报价与释放 | 后端 | 金额只由后端工具计算 |
| 报价任务、订单绑定、付款状态机 | 后端 | 插件只读取权威订单并执行动作 |
| 提示词、知识库、评测、人工复核 | 后端 | 统一版本化和审计 |

## 插件动作白名单

当前生产执行器只允许：

- `send_message`
- `change_order_price`
- `send_price_change_confirmation`

新增动作必须同时具备：后端 schema、插件参数校验、权限、幂等键、超时结果对账、审计记录和回归测试。未知动作一律跳过并回报原因。

## 安全门禁

- `WANDA_EXTERNAL_WRITES_ENABLED=false`时停止领取外部写命令，不切换旧引擎。
- 读取不到最新会话时禁止发送陈旧回复或改价。
- 改价前必须校验 tenant/shop/buyer/chat/order/quote 全部绑定一致。
- 已付款、退款、关闭或状态未知的订单禁止改价。
- 改价后必须再次读取订单，金额一致才算成功。
- 平台结果未知时先对账，不盲目重复写操作。
- 本地事件、动作回执与面板长任务使用加密存储；生产只允许单实例，扩为多实例前必须迁移到支持原子租约的共享存储。
- 发往业务后端的订单上下文必须使用 `executor_next.authoritative_order.v1` 脱敏快照，不得转发平台原始订单对象；收件人敏感字段只能经独立敏感信息端点按需读取。

## 发布边界

生产包只包含 `index.mjs`、`src/`、manifest、运行 SDK、Dockerfile、本说明和已接线的 `ui/` 运行状态面板。以下内容必须排除：

- `data/`、`.env*`、`node_modules/`
- `test/`、`evaluation/`、`tools/`、`datasets/`
- 未接线的运营配置、评测与开发页面
- `图片学习样本/`
- Playwright、pytest、coverage 和临时文件

## 后续阶段

1. 先稳定插件执行器和后端契约，不恢复任何旧插件 bridge。
2. 在 `ticket-system-local` 收敛 Agent、工具、报价和会话状态。
3. 鱼麦多面板只展示经过网关签名认证的执行器状态与安全边界；业务运营配置仍由独立后端管理。
4. 受控联调通过后再启用单测试店 auto；真实改价回读通过前保持自动改价关闭。
