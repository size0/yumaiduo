## 二、★★★ Bug 1：模型看到的出票时效是错的（已修）

### 2.1 冲突现场

```
你配置的 precautions:
  「多久出票」→ 回答付款后 1-30 分钟（最迟 50 分钟）

代码实际的时效（按实际档位，templates.TICKET_WINDOW）:
  距开场 ≤15 分钟 → FLASH    = 1-15 分钟
  距开场 ≤40 分钟 → FAST     = 15 分钟内
  距开场 >40 分钟 → STANDARD = 1-60 分钟    ← ★ 最常见
```

**你那两张图的场次（12:40 / 20:35，离开场都 >40 分钟）实际都是 STANDARD。
报价卡和 TICKETING 上写的就是「1-60 分钟」。**
**而买家问"多久出票"，模型会照配置说 1-30 分钟 —— 两个数打架。**

### 2.2 templates.py 里早就论证过这件事

```
★ 为什么不能写死成「1-30分钟（最迟50分钟）」：
  票达人页面上写的是 1-30/50，但良票文档里 STANDARD 是 1~60。
  我们买的如果是 STANDARD，却告诉买家 30 分钟，就是【对买家说了不准的话】——
  超时的那一单会变成投诉。所以时效必须跟着实际购入的档位走。
```
**⇒ 你配置里填的正好就是那个被点名的数。但根因不在你的配置，在代码 —— 模型看不到真实时效。**

### 2.3 根因

```
_window(conv)  → 只在【报价卡/TICKETING 文案】里用
context_from(conv, order)  → 给模型看的事实块
                             ★ 里面【没有时效】
⇒ 模型只能照 precautions 里写死的数字答
```

### 2.4 修法（纯只读，不碰钱）

```python
# conversation_ai.py 新增
def _ticket_window_of(conv) -> str:
    if getattr(conv, "quote", None) is None:
        return ""                                  # 没报价就不谈时效
    mode = str(getattr(conv, "ticket_mode", "") or "").strip()
    if not mode:
        return ""                                  # ★ 不知道就返回空，不许编
    return tpl.TICKET_WINDOW.get(mode, "")

# context_from 里加一行
ticket_window = _ticket_window_of(conv)
if ticket_window:
    lines.append(f"· 出票时效：{ticket_window}"
                 f"（买家问\"多久出票\"就照这个答，不要说别的数）")
```

**★ 我第一版写成 `or TICKET_STANDARD`，结果档位为空时返回 "1-60分钟" ——
那正是这个函数要消灭的"编一个数"。已改成返回空。**

**★ 注释里我也写了具体数字，被 `_check_params` 抓住了**（"代码里只有一处定义出票时效"）
—— 那条检查是对的（时效的唯一定义处就是 `templates.TICKET_WINDOW`），
**我改了注释，没改检查。**

### 2.5 实测

```
档位 STANDARD → 模型看到 '1-60分钟'
档位 FAST     → 模型看到 '15分钟内'
档位 FLASH    → 模型看到 '1-15分钟'
档位 ''/None/'UNKNOWN' → ''（不编）
还没报价      → ''（不承诺）
```

## 三、★★★ Bug 2：万达单的「档位」被渠道名顶了（已修）

### 3.1 现场

```python
# 万达分支（修之前）
self._stash_quote(conv, result, seat_names, "WANDA", quote, ...)
#                                          ↑ 第 4 个位置参数是 ticket_mode（档位）
#                                            却传了【渠道名】

# _stash_quote 内部
conv.ticket_mode   = ticket_mode                          # ← 当档位用
conv.quote_channel = "WANDA" if ticket_mode == "WANDA" ...# ← 又当渠道用
conv.channel       = "wanda" if ticket_mode == "WANDA" ...
```

**⇒ 一个参数被当成两个维度用。**

**后果：万达单 `conv.ticket_mode = "WANDA"`，
而时效表只有 `STANDARD/FAST/FLASH` ⇒ 查不到。**
```
_window()                  → 靠 .get(..., TICKET_WINDOW["STANDARD"]) 兜底才拿到 1-60
_ticket_window_of()        → 查不到就是【没有时效】
⇒ 万达单（也就是我们现在的主渠道）的时效，从来不是算出来的，是兜底来的
```

### 3.2 ★ 危险点：不能只把 "WANDA" 换成档位

```
如果直接把第 4 个参数改成档位：
    conv.quote_channel = "WANDA" if ticket_mode == "WANDA" else "LIANGPIAO"
                       = "LIANGPIAO"          ← ★ 判错了！
⇒ 万达的单被确认后会拿万达的 showtimeId 去调【良票下单】
   那是真下单，动钱。
```

### 3.3 修法：拆成两个参数

```python
def _stash_quote(self, conv, result, seats, ticket_mode, quote, params, out,
                 *, channel: str = "") -> None:
    conv.ticket_mode = ticket_mode            # ★ 只可能是 STANDARD/FAST/FLASH
    chan = str(channel or "").upper()
    if chan not in ("WANDA", "LIANGPIAO"):    # 没传就退回旧行为，保证兼容
        chan = "WANDA" if ticket_mode == "WANDA" else "LIANGPIAO"
    conv.quote_channel = chan
    if not getattr(conv, "channel", ""):
        conv.channel = "wanda" if chan == "WANDA" else "liangpiao"
```

**万达分支同时要【真的算出档位】——它原来压根没算：**
```python
wanda_tier = TICKET_STANDARD
try:
    wanda_tier = self.api.pick_ticket_mode(result.start_time)
except Exception as exc:
    out.notes.append(f"★ 算不出票速档位（{type(exc).__name__}: {exc}）"
                     f"—— 按特惠档记，时效按 1-60 分钟")
self._stash_quote(conv, result, seat_names, wanda_tier, quote,
                  QuoteParams(), out, channel="WANDA")
```
**★ 为什么万达单也需要档位**：买家问"多久出票"，我们得照实际档位答 ——
时效是对买家的承诺，答宽松了出事、答严了显得慢。
`pick_ticket_mode` 是纯函数（只按时间算，不调任何接口），所以万达单也能用。

**良票分支显式传 `channel="LIANGPIAO"`。**

### 3.4 实测（三个档位 × 三个维度）

```
档位 STANDARD → conv.ticket_mode='STANDARD' ✓  quote_channel='WANDA' ✓  channel='wanda'  模型看到 '1-60分钟'
档位 FAST     → conv.ticket_mode='FAST'     ✓  quote_channel='WANDA' ✓  channel='wanda'  模型看到 '15分钟内'
档位 FLASH    → conv.ticket_mode='FLASH'    ✓  quote_channel='WANDA' ✓  channel='wanda'  模型看到 '1-15分钟'
良票单        → quote_channel='LIANGPIAO' ✓
```

## 六、★★ 有一条我没动，要你定

**你的 `precautions` 里那句「1-30 分钟（最迟 50 分钟）」还在。**
现在代码已经把**真实时效**给模型了，而且明确写着
**"买家问「多久出票」就照这个答，不要说别的数"** ——
理论上模型会照事实块答。

**但两处口径并存仍然是隐患**（模型可能同时看到"照事实块答"和配置里那个数）。
**你的话术我不擅自改。** 两个选项：

```
① 把 precautions 里那句改成不带数字的写法，例如：
     「多久出票」→ 照系统给我的「出票时效」回答，不要自己说别的数
   （推荐：时效只有一个来源，以后档位改了不用再改配置）

② 保持现状（靠事实块里的"照这个答"压过它）
```
