# 改造：原子组件层（照《UI 架构规范》§3）

> 日期：2026-10-14
> 店主：「接着做原子组件层」
> 规范 §3 要求 7 个原子组件；§8 第②步的验收是
> 「一个组件预览页，把每个变体排一遍，**不出现色值**」。

![组件预览](img/components.png)

---

## 一、为什么是这套形态（不是 React 组件）

规范 §6 自己写着：「**先不要引入** redux / 状态机 / react-query ——
先用 hooks + 1~2 个 Context，等出现真实痛点再上」。
我们是**原生 HTML + CSS + 服务端直出**，连框架都没有。

⇒ 最合适的"组件层"是这三件：
```
① web/ui.css   语义类名 + CSS（变体只认类名）
② web/ui.js    元素工厂 + cn()（不让调用方拼类名字符串）
③ /components  预览页（把每个变体排一遍 —— 规范的验收载体）
```
**引入框架是另一件事**（收益不明确、改动面覆盖全部页面），没做。

## 二、7 个组件

| 组件 | 变体 / 参数 |
|---|---|
| `Button` | `variant`(primary/secondary/outline/ghost/danger/link) × `size`(xs/sm/md/lg) + `loading` + `leftIcon/rightIcon` + `disabled` |
| `Card` | `padding`(sm/md/lg) + `title` + `body` + `className` 透传 |
| `Input` | 原生 props + `error`（错误态 + 说明文字） |
| `Tag` | `variant`(default/brand/success/warning/danger/info) + `size` + `dot` |
| `PageHeader` | `title` / `subtitle` / `actions` |
| `Empty` | `icon` / `title` / `description` / `action` |
| `cn()` | 类名合并：去重、过滤假值、后者覆盖 |

**★ 变体只认名字**（规范原话：「不接受自定义色值」）——
`Button()` 和 `Tag()` 都会**校验变体名，拼错直接抛错**：

```js
throw new Error('Button: 未知 variant "primry"，可选：primary / secondary / …');
```
**为什么不静默忽略**：静默的后果是"生成了一个没有样式的按钮"，
那种最难查（页面能用、就是难看，而且不知道谁写的）。

## 三、★★★ 最要紧的一条：组件层里没有一个具体色值

规范 §1 的硬性禁令 1：「业务组件里**禁止出现具体色值**」。

```
ui.css   0 处
ui.js    0 处（★ 有一条断言专门扫这两个文件）
```

**为什么这条是这套架构的核心**：
```
写死一个 #fff，页面照样正常显示 —— 看不出问题。
问题只在【换主题时】暴露：那一处不会跟着变，到处漏色。
⇒ 所以只能靠断言守，靠眼睛守不住。
```

**Tag 的底色是这么写的**（不另写 rgba）：
```css
.ui-tag--success {
  color: var(--success);
  background: color-mix(in srgb, var(--success) 16%, transparent);
}
```
★ 好处：以后改 `--success`，这 6 个变体全跟着变；
写 rgba 的话就得改 6 处。

## 四、★ 顺手修的一个真问题：主色不跟主题走

建组件时发现：**`--accent` 是固定蓝 `#0a84ff`，主题只改 `--bg-base`**。

```
实测：主题 mist → mint，主按钮底色完全不变（都是 rgb(10,132,255)）
⇒ 店主在色盘上选「薄荷」，只有背景变绿、按钮还是蓝的
   —— 看起来像"没生效"
```

**修法**：`--accent` 改成引用 `--bg-accent`（就是主题选的那个色）。

```
实测（修后）：mist=rgb(91,124,250) 蓝   mint=rgb(47,174,134) 绿
             rose=rgb(232,116,158) 粉   ink=rgb(43,58,74) 灰
```
★ 为什么这是对的而不是将就：色盘上每个主题就是**一个颜色**。
店主选颜色时想的是"整个界面的主色换成这个"，不只是背景。
复用同一个令牌 ⇒ 背景光斑和主色同色系，天然协调；
自定义色也走同一条路（theme.js 设行内 `--bg-accent`）。
`--accent-soft` 也跟着改（否则选中态底色还是蓝的）。

## 五、断言（新增 8 条）

```
★  组件层文件在：ui.css / ui.js / components.html
★★ 规范要求的 7 个原子组件都在 ui.js
★★★ 组件层里没有一个具体色值（规范禁令 1）   ← 最关键
★★ Button 只认 variant 名（不接受自定义色值）
★  Tag 底色用 color-mix 从令牌算（不另写 rgba）
★★ 组件预览页存在且能换主题
★  /components 路由已接
```

**★ 断言自己抓到我一次"说了没做"**：
我原来只在注释里写了"Button 只认变体名"，**没有真的白名单**。
断言 `all(v in _uijs for v in ("primary", ...))` 直接失败 ⇒ 补上白名单 + 校验。

**★ 两个假阳性也修了**（断言的正则）：
```
· `white-space: nowrap` 里的 white 不是颜色
  ⇒ 正则加 (?<![\w-])…(?![\w-]) 词边界
· `transparent` / `currentColor` 是合法关键字，不算"具体色值"
```
