# 操作台文案规范：不许出现"光秃秃的英文"

> 日期：2026-10-14
> 店主原话：**「操作台不要写英文　有英文参数必须（）写中文注释」**

---

## 一、这条规则的准确含义

**不是"不许有英文"** —— 有一批英文是**必须保持原样的**：
环境变量名、接口路径、模型名、错误码、字段名、系统生成的编号。

**真正的要求是分两类：**

| 类别 | 要求 | 例子 |
|---|---|---|
| **界面文案**（标签 / 表头 / 按钮 / 提示） | **不该只有英文** —— 要写中文 | ~~`API Key`~~ → `接口密钥（API Key）` |
| **必须原样的标识符** | 允许是英文，但**必须配中文注释** | `YUMAIDUO_WEBHOOK_SECRET`（鱼麦多网页回调密钥） |

**判据**：那段英文**旁边有没有中文解释**。

## 二、改之前扫出来的（用真浏览器看"渲染后眼睛能看到的字"）

```
合计纯英文可见文字：34 处
  /qa      20 处   引用编号（a6d4dqvkluc 这类）
  /orders  13 处   环境变量名 / quote_id / 上游单号
  /shops    1 处   PLUGIN_SECRET_MISSING（错误码）
```

**★ 为什么必须用浏览器扫，不能扫源码**：
源码里全是属性值（`class` / `id` / `href` / `aria-*`），
正则一扫几千条噪音，"真正显示出来的英文"会被淹掉。

## 三、逐项怎么改的

### ① 模型下拉（最典型）

模型名是**发给模型的真实名字**，改了就调不通 ⇒ 只能标注：

```
后端 settings.py 加 model_labels：
    "deepseek-flash":  "极速版"
    "deepseek-v4-pro": "增强版"
后端 server.py 把它透传给前端（白名单字典，必须显式加）
前端 app.js  渲染成 「极速版（deepseek-flash）」
             ★ option 的 value 仍然是英文名 —— 存进配置的就是它
```
**★ 这里有个坑**：如果保存时取的是 option 的**文字**而不是 `value`，
存进配置的就变成"极速版（deepseek-flash）"，模型调用会失败。
检查过：`model.value` ✓。

### ② 英文参数配中文注释

```
web/config.html   AppKey      → 应用标识（AppKey）
                  AppSecret   → 应用密钥（AppSecret）
                  tel         → 购票手机号（tel）
web/index.html    API Key     → 接口密钥（API Key）
                  system prompt → 系统提示词（system prompt）
web/rules.html    priceMode=FIXED → FIXED（一口价）
                  priceMode=LIMIT → LIMIT（限价）
web/rules.js      priceMode（报价模式）= …（一口价：报价即成交价）
                  maxPrice（总限价）
web/orders.html   quote_id    → quote_id（报价单编号）
```

### ③ 环境变量名：一条一条配说明

```
WANDA_TICKETING_DELIVERY_KEY            （出票接口密钥）
WANDA_TICKETING_INTEGRATION_TENANT_ID   （允许出票的租户编号）
WANDA_TICKETING_INTEGRATION_SHOP_IDS    （允许出票的店铺白名单，逗号分隔）
WANDA_TICKET_DELIVERY_ENABLED           （出票写开关，true 表示允许）
YUMAIDUO_WEBHOOK_SECRET                 （鱼麦多网页回调密钥）
YUMAIDUO_AUTO_REGISTER=true             （"鱼麦多自动注册"开关设为 true）
V5_BACKEND_SECRET_FILE                  （后台密钥交接文件路径）
x-yumaiduo-signature                    （鱼麦多签名）
```

### ④ 标识符：在值旁边加中文小标签

有些值是**系统生成的编号**，本身就长那样（小写字母数字），
不可能翻译 ⇒ 在它前面加个中文小标签：

```
/qa      引用编号 · ggx1z82tg84
/orders  上游单号 · LP-UPSTREAM-9
/shops   错误码 · PLUGIN_SECRET_MISSING
```

### ⑤ 平台状态码：中英对照

```
shops.js 加 STATUS_CN 对照表：
    online       → 正常（online）
    risk_pending → 风控审核中（risk_pending）
    …
★ 认不出来的状态码【原样显示】：
  宁可露出英文，也不要把一个没见过的新状态悄悄显示成"正常"。
```

### ⑥ 买家的中文说明也顺手改了几处

```
"POST 一个订单号"  → "发一个请求（POST）带上别人的订单号"
"Bearer 密钥"      → "令牌密钥（Bearer）"
"缺 account.read 权限" → "缺 account.read 权限，即"读取账号"授权"
"设 YUMAIDUO_TENANT_ID" → "设 YUMAIDUO_TENANT_ID（鱼麦多租户编号…）"
```

## 六、★ 一条判断标准（写给以后的自己）

**看到英文时先问一句：这串英文能不能改成中文？**

```
能改      → 直接改中文（"API Key" → "接口密钥"）
改不了    → 加中文注释，并且尽量写成「中文（英文原样）」
            （英文在前还是中文在前，看哪个是"给人看的"）
```

**绝不做的两件事：**
1. **把标识符翻译掉** —— 环境变量名、字段名、模型名、错误码
   翻译了就不再是它自己，功能直接坏掉。
2. **把认不出的值统一显示成中文兜底** —— 比如把未知状态码显示成"正常"。
   那会把"平台出现了新状态"这件事藏起来，比露出英文危险得多。
