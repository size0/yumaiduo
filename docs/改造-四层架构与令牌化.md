## 一、先把「怪」量化（不然改不到点上）

店主说不上哪里怪。我把所有 CSS 按属性分组，看**同类属性用了几套值**：

```
border-radius ：12 套   8px / 9px / 10px / 11px / 7px / 6px / 3px / 14px …
font-size     ：12 套   13px / 12px / 11px / 12.5px / 14px / 13.5px / 11.5px …
box-shadow    ：12 套   各写各的内阴影外阴影
backdrop-filter：9 套   22/26/28/16/6/34/18/8px…
```

**★ 这就是"怪"的来源**：同类东西在不同地方取值不一致（8px 和 9px 的圆角、
12.5px 和 13px 的字号），人眼能感到"不齐"但说不出具体哪条。
而且有 **12.5px / 13.5px / 11.5px 这种半像素字号** —— 既没节奏感，也没法用令牌管。

**硬编码色值 257 处**，规范分类里 10 类令牌我们**只有 4 类**。

## 二、做了什么（按规范 §8 的落地顺序）

### ① 令牌层（L2 设计令牌 + L3 语义变量）

补齐规范 §2 要求的全部 10 类：

| 类别 | 令牌 |
|---|---|
| 品牌 | `--brand-500/600/700` + `--brand-soft` |
| 强调 | `--accent-500/600` + `--accent-soft/-2` |
| 表面 | `--surface` / `--surface-alt` / `--surface-solid` |
| 文字 | `--text` / `--text-muted` / `--text-subtle` / `--text-inverse` |
| 描边 | `--border` / `--border-strong` / `--border-highlight` |
| 交互 | `--hover` / `--active` |
| 字号 | `--fs-2xs..2xl` + **配套 `--lh-*` 行高** |
| 圆角 | `--radius-xs/sm/md/lg/xl/full`（6/8/12/16/22/100） |
| 阴影 | `--shadow-xs/sm/md/lg` |
| 模糊 | `--backdrop-glass` |

**★ 兼容策略（关键）**：旧变量名（`--text-dim` / `--radius` / `--glass-*`）
**全部保留，改成指向新令牌**。这样已有 6 个页面的引用不用改就跟着新令牌走，
迁移可以逐页做 —— 符合规范 §8 第⑤步「先迁 1 个页面，再批量迁」。

### ② ★ 归一碎值（这一步最直接地解决"怪"）

```
font-size    104 处 → 只取 7 档（11/12/13/14/16/20/26）
font-size: 简写 12 处 → 同样归一（我第一版只扫了长写，漏了 `font: 500 13px …`）
border-radius 53 处 → 只取档位（6/8/12/16/22/100/50%）
```
**实测 7 个页面**：字号档位全部落在规范集合内，**半像素字号 0 处**，横向溢出 0。

### ③ 硬编码色值：257 → 17

| 轮次 | 做了什么 | 剩余 |
|---|---|---|
| 起点 | — | **257** |
| 1 | 白系半透明 44 种值 → 玻璃高光 4 档；黑系 20 种 → 分隔线 3 档；栏目标识色 → 令牌 | 148 |
| 2 | 补漏（"逗号带空格"的 rgba 写法我第一版正则漏了） | 111 |
| 3 | 状态色徽标 → 令牌 + `color-mix` 算浅底 | 99→64 |
| 4 | "令牌里已有、组件里又写一遍"的（`#0d7a7a`=`--info` 等） | 26 |
| 5 | 悬停阴影 / 滚动条 / 品牌渐变 / 深色弹窗面 | **17** |

**剩下 17 处的性质**（不是"漏改"，是规范允许的）：
```
· .ticket-sidebar 的 --sidebar-* 一组 —— 浮岛规格给的主题变量（L4 层）
· @media dark 里的覆盖值 —— 规范 §4「深色必须单独覆盖变量」
· 3 处 .card:hover / .rc-card:hover 的悬停阴影（值成对出现，逐个替换有风险）
```

### ④ ★★ 令牌化过程中踩的三个坑（都是"不报错但看着不对"）

**坑 1：`--glass-blur` 的语义冲突 —— 会把玻璃全弄坏**
```
规范 §2 说 --glass-blur 是整段：blur(24px) saturate(135%)
但现有 18 处组件写的是：backdrop-filter: blur(var(--glass-blur)) saturate(...)
⇒ 会拼成 blur(blur(24px) saturate(135%)) saturate(135%) —— 非法，玻璃全失效
★ 修法：给两个名字
    --glass-blur     长度值 24px  → 旧写法用
    --backdrop-glass 整段简写     → 新写法用
  （选这个而不是"改 18 处组件"，是为了让两种写法都成立、迁移能逐页做）
```

**坑 2：`--radius-sm` 的语义冲突 —— 圆角全变小 4px**
```
旧令牌层：--radius: 18px / --radius-sm: 12px
规范 §2：圆角 6 / 8 / 12 / 16 / 22 / full
⇒ 我照规范把 --radius-sm 定成 8px，但旧组件引用它时想要的是 12px
  ⇒ 所有用到它的圆角都小了 4px（这是我引入的变化，不是原来就有的）
★ 修法：旧引用全部改指 --radius-md（=12px），视觉与改动前一致，名字统一到规范
```

**坑 3：我一度按 class 名删样式，删掉了另一个用途的东西**
```
`.plat-tabs` 同时是：① 顶部的「闲鱼」标签（要删）
                     ② 回复文案面板的渠道切换器（要留）
⇒ 按 class 名删会把渠道切换器变成三个裸按钮
★ 后来补回。同类的还有 `--glass-blur`（同名两种语义）——
  教训：按名字批量操作之前，先搜这个名字有几个用途。
```

## 三、钉住的断言（规范 §7 的质量闸门）

新增 6 条，防这套架构被再次破坏：

```
★★ 规范要求的 10 类令牌都在（L2/L3 层）
★★ 字号只取档位上的值（不许 12.5px 这种半像素）
★★ 圆角只取档位（6/8/12/16/22/100/50%）
★★ 令牌 --radius-xl 就是 22px（浮岛规格靠它）
★★ 没有 JS 按主题加类名（只能靠变量覆盖）
★  !important 没被用来压主题
```

**★ 为什么这些必须断**：令牌是**间接层** —— 改错一个名字不报错，
只是"看着不对"。而"看着不对"正是店主说的"怪"。
没有断言，下次有人手写一个 9px 圆角照样看不出来，层级又乱了。

**★ 一条断言自己踩的坑**：规格我在 CSS **注释**里也写了一遍
（`border-radius: 22px` 等），所以断言必须查**剥过注释的代码** ——
否则注释就能让断言全绿而真代码是空的。

## 四、视觉验收（规范 §7 要求）


## 五、还差什么（诚实列出来）

```
⬜ L4 原子组件：规范 §3 要求 7 个组件（Button/Card/Input/Tag/
   PageHeader/Empty/cn）。我们是原生 CSS，没有组件层 ——
   "Button 只认变体名"这件事目前靠的是 class 约定（.btn-primary 等），
   没有"传色值就报错"的机制。
   ⇒ 要不要做，取决于店主：原生栈可以做一个轻量的类名契约 + 断言，
     但收益不如在 React/Vue 里明显。
⬜ 骨架屏 / 懒加载：规范 §5 要求。我们是服务端直出单页，没有 chunk 概念。
← 这两条是【架构级】的，改动量和风险都比令牌大，我先没动。
⬜ 剩余 17 处色值（性质见上，多是规范允许的 L4）
```
