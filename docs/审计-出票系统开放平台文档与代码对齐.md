## 二、★★★ 5.1 的语义描述是旧行为

### 文档原文（395-401 行）

```
语义：服务端按 create_order.api 临时锁座 → 读 /mkt/activity/secret/list.api 的
      W+会员专享优惠 → 返回会员价与分摊，查询结束会自行释放座位。

★ 会员价的来源是锁座后的活动分摊（allotSeat），不是座位图里的 areaPrice.salesPrice。
实测：6排8座（优选区）原价 ¥34.90 → W+ 优惠 −¥4.00 → 会员价 ¥30.90；
      8排15座（W+专享）原价 ¥53.90 → −¥6.00 → ¥47.90。
会员价构成：salePrice + servicePrice + channelPrice。
```

### 代码实际是【双模】

```python
# app/routes/order.py:324-344   请求模型
probe: bool = False
    # False is always read-only for no-selection requests.
partition: str = ""
    # Empty for read-only W+ area preview or an explicit physical-seat probe.

# app/routes/order.py:887-908   路由 docstring
"""Quote W+ through the existing backend-owned Wanda account pool.

Empty seat requests are read-only realtime previews. Selected-seat requests
may use the temporary lock/cancel probe when explicitly enabled.
"""

# app/routes/order.py:912-917   关键分支
no_selection = not req.seat_ids and not req.partition
if not 1 <= req.ticket_count <= 6:
    raise HTTPException(400, "ticket_count 必须为 1 到 6")
if no_selection and not req.probe:
    return await _internal_wplus_realtime_preview(req)      # ★ 只读，直接返回
if not settings.wanda_quote_enabled or not settings.wanda_wplus_probe_enabled:
    raise HTTPException(409, "W+官方核价探针未启用，请先完成联调")
# ↓ 到这里才走锁座/取消
lease = store.acquire_account_lease(phone, req.request_id,
                                    "plugin-wplus-quote", ttl_seconds=120)
```

**三种模式：**

| 输入 | 走哪条 | 读/写 |
|---|---|---|
| `seat_ids=[]`、`partition=""`、`probe=false` | `_internal_wplus_realtime_preview` | **纯只读** |
| 同上但 `probe=true` | 探针（锁座→活动→取消→恢复） | 写 |
| 给了 `seat_ids` 或 `partition` | 探针 | 写 |

### 建议改法

把 395-401 行改成三段：先讲**默认只读**（并指向 4.3 的 `wPlusActivity.price`），
再讲**显式 probe**（要 `WANDA_QUOTE_ENABLED` + `WANDA_WPLUS_PROBE_ENABLED`，
未启用返回 **409**），最后保留原有的分摊说明作为"探针模式的返回值"。

同时在参数表补上：

| 字段 | 必填 | 真实约束（代码） |
|---|---|---|
| `ticket_count` | 否 | 默认 1，**必须 1~6**，否则 400 |
| `probe` | 否 | `true` 时需要服务端已启用探针开关，否则 **409** |
| `partition` | 否 | 给了它就走探针；格式 `_partition_seat_ids` 会校验 |
| `seat_ids` | 否 | 给了它就走探针；1~6 个、不重复、且必须与 `ticket_count` 数量一致 |

★ 还有一个**请求模型是 `extra="forbid"`** —— 多传字段会 422。文档该写明。

## 九、★★ 5.1 只返回"会员区"——这会漏区域（**这条是代码本身的问题，不只是文档**）

### 代码

```python
# app/routes/order.py:643-644
is_wplus_area = bool(re.search(r"W\s*[+＋]|WPLUS|会员专享", area_name, re.IGNORECASE))
is_wplus_area = is_wplus_area or any(_is_wplus_seat(seat) for seat in seats
                                     if isinstance(seat, dict))
if not is_wplus_area:
    continue
```

### 实测后果（场次 103155652）

```
桥 /seats 读到 4 个有会员价的区域：
    area=1   普通区  会员价 37.51   原价 42.90
    area=32  优选区  会员价 42.61   原价 48.90
    area=33  特惠区  会员价 35.00   原价 37.90
    area=36  W+专享  会员价 42.61   原价 48.90

wplus-price 只返回 1 个：
    area=36  W+专享  会员价 42.61   ✓ 与桥一致
```

**⇒ 排除规则是"区域名含 W+ / 会员专享" 或 "有 payMemberSeatStatus=1 的座位"。
「普通区/优选区/特惠区」两者都不满足，所以被跳过 —— 但它们确实有会员价。**

### 为什么这是问题

**如果买家选的是「优选区的某个座位」，`wplus-price` 不会返回优选区的价**，
只返回 W+专享区的。接入方拿它报价就会报错价（这里是 42.61 vs 应取优选区 42.61
—— 本场恰好相等，但**普通区 37.51 / 特惠区 35.00 的差异就体现出来了**）。

### 建议（两条路选一）

```
A. 放宽为：只要 area.wPlusActivity.price 是正数就算有会员价
   （最直接，和座位图口径一致）
B. 保留"会员区"过滤，但【另外】返回所有有会员价区域的清单，
   并在文档里说明"wplus_areas 只列 W+ 会员区，
   普通/优选/特惠区的会员价请从座位图的 area[].wPlusActivity.price 取"
```

★ **无论选哪条，文档都必须写明这条过滤规则** —— 现在接入方无法从文档知道
"为什么我选了座位，返回的却是另一个区"。
