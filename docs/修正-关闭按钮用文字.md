# 修正：关闭按钮用文字「关闭」，不是 ×

> 日期：2026-10-14
> 店主：「我需要关闭　文字　不要 ×」
> **★ 我上一轮把方向搞反了。**

![回复文案弹窗](img/replies-modal.png)

---

## 一、我上一轮错在哪

店主说的是：
```
「新增关键词右上角的关闭按钮 也和 回复文案中的关闭按钮 做成一样」
```
**基准是【回复文案那个】**，而它原本就是**文字「关闭」**（`.btn` 胶囊）。

我却按"× 更常见"把**两个都改成了 ×** —— 那不是店主的要求，是我的偏好。
**结果等于把基准也改坏了。**

> ★ 教训：说「A 和 B 做成一样」时，要先问自己**谁向谁看齐**。
> 我这次凭"哪个更常见"选了一个，而不是"哪个是基准"。

---

## 二、改回来

```
✓ 回复文案弹窗：× → 文字「关闭」（60×31 胶囊，沿用 .btn）
✓ 关键词弹窗：  × → 文字「关闭」（同上，两个完全一致）
✓ style.css：去掉 × 的专用样式（不再需要）
```

**实测两个弹窗的关闭按钮完全一致**：
```
回复文案：text='关闭' class=btn 60×31 圆角100px 背景 rgb(255,255,255)
关键词：  text='关闭' class=btn 60×31 圆角100px 背景 rgba(255,255,255,.86)
```

**★ 顺手去掉底部按钮条的「取消」** ——
它和右上角「关闭」是同一件事，两个文字按钮并排容易让人不知道该点哪个。
底部只留**【保存】在右下角**（店主指定的位置）。

---

## 三、★★ 这个改动引出一个静默失效的 bug

去掉「取消」按钮后，`qa.js` 里这一行还在：
```js
$('btn-cancel').onclick = closeModal;
```
**元素删了 ⇒ 抛 `Cannot set properties of null`。**
而它在**启动路径上**（`DOMContentLoaded` 里）⇒

```
后面那些绑定全都不执行：
   $('btn-save').onclick = ...      ← 保存失效
   $('btn-del').onclick  = ...      ← 删除失效
```

**页面看着完全正常**，"新增关键词"照样能打开弹窗（那行在报错之前），
**但点保存没反应** —— 这是最难发现的一类问题。

**我是靠"两个弹窗都测一遍、顺手看 JS 报错"抓到的**，不是靠读代码。

**⇒ 已修**，并加了断言：
```
★★ JS 里没有绑到已删按钮上的 onclick（会抛 null 废掉后续绑定）
```
实测：`saveBound: True, delBound: True, JS 报错: 无`
