## 一、我为什么改主意（上一轮我把它列进了"不接"）

上一轮我说：`auto_recognize` 只有 label、没有 hint，语义不明，不敢接。

**现在我找到了能确定的那一半**：
```
字段定义里没有 hint ⇒ 但有【一个能确定的部分】：
   关掉它 = 【不自动】走识别那条路。

而"不自动"在这套系统里的含义是 **已经有的** ——
   系统里本来就有"转人工"这条路径（AI_HANDOFF 模板 + need_human 字段）。
⇒ 关掉自动识别就该走它，而不是我发明第三种行为。
```

**语义定为**：
```
开（默认） ⇒ 买家发选图就自动识别（现在就是这样）
关         ⇒ 不自动识别；走已有的转人工路径，标记 need_human（店家手动录）
```

**★ 三个"最小改动"的取舍**：
```
① 复用【已有的】 AI_HANDOFF 模板 + need_human 字段 ——
   没有新增话术、没有新增状态
② 默认开着 ⇒ 默认行为一个字不变
③ 没有自己发明"回一句话让买家自己填影院/场次/座位"那种新行为 ——
   那是另一种语义，要店主确认
```

**实测**：
```
开（默认）：need_human=False  notes=[]
关        ：need_human=True   template_keys=['AI_HANDOFF']
            notes=['★ 自动识别报价=关 ⇒ 不自动识别这张选座图，转人工（等店家手动录）']
```

**★ 如果店主想要的是别种行为**（比如"让买家自己填影院/场次/座位"），
改 `service.py` 里图片分支的那一段即可 —— 我把它写在一处、标了注释。

## 二、★ 一条判断规则，我这轮想清楚了

上一轮我把 6 类全列进"不接"，理由是"语义不明"。**这个判断太粗了。**

**更准的判据**：
```
能确定【关掉之后不该做什么】  ⇒ 可以接，而且走已有的路径
只能猜  【关掉之后该做什么】  ⇒ 不能接
```
* `auto_recognize`：能确定"关掉就不该自动识别"，
  且系统已有"转人工"这条现成路径 ⇒ **能接**（本轮接了）
* `fallback_quote.mode`：关掉/改成"一口价"之后**该报多少钱**？
  没有任何现成路径可依 ⇒ 不能接（猜错就是报错价）

**⇒ 这条规则让"不接"的每一项都有具体理由，而不是笼统的"语义不明"。**
