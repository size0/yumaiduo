# V5 万达链路 vs 我们 —— 查证结果

> 来源：V5 生产快照 `v5-prod-9bee216/backend/app/providers/`（只读查证）。
> 目的：搞清「万达为什么不能用现在的报价通路」，以及接它要做什么。
>
> ★ 结论先说：**万达不是"再加一条报价规则"能解决的** ——
>   它的成本口径、定价、下单、出票**四条链全和良票不一样**。

## 二、渠道判定：用 hall 名，不是品牌名

```python
# v5 providers/wanda/cost.py:31-33
if 'VIP' in str(show.get('hall') or request.hall or '').upper():
    cost = (provider._legacy_exact(...) if selected
            else provider._legacy_wplus(...))
```

**⇒ V5 靠 `hall` 字段里有没有 "VIP" 来分岔。** 不是靠 `brandName`。

我们那边：识别结果有 `brand_name = '万达影城'`，**但 hall 名是 `3号激光厅-会员卡享29.9元起观影`** ——
按 V5 的判据它**不含 "VIP"**，会走普通分支，然后在 W+ 会员价那层被拦住（我实测 `preflight 可用=False` 就是这个原因）。

**★ 这里有个没对齐的点：我们需要确认"会员场"到底怎么判。** V5 用 hall 名，但实际线上线下可能有别的标志位。

## 三、成本：三层级联（这是我们的最大缺口）

```
v5 providers/wanda/cost.py
```

| 优先级 | 来源 | 触发条件 | cost_source |
|---|---|---|---|
| 1 | **座位价** `seat.priceFen` | 座位图里直接有价 | `EXACT_SEATS` |
| 2 | **W+ 会员价** `wPlusActivity.price`（区域级）或 `wplusPriceFen`（座位级） | 座位图里有 wplus 标记 | `REALTIME_WPLUS_MEMBER_SEAT_PRICE` |
| 3 | **内部桥 probe** | 上面都拿不到价 | `INTERNAL_WPLUS_BRIDGE` |

**③ 内部桥**（`internal_bridge.py` 305 行）是关键兜底：
```
真下临时单 → 读价 → 取消   （preview.py 的 create/read_price/cancel）
```
走的是万达内部接口：`/order/create_order.api`、`/order/order_status.api`、`/order/cancel.api`、`/mkt/activity/secret/list.api`

### ★ 硬校验（不猜，宁可拒绝报价）

```python
# cost.py:54-66
不同座位的会员价不一致     → WPLUS_MEMBER_SEAT_PRICE_AMBIGUOUS
会员价 > 原价              → WANDA_COST_UNAVAILABLE
多个不同会员价             → WPLUS_MEMBER_SEAT_PRICE_AMBIGUOUS
候选座位 < 需要的张数       → 走桥，桥不可用就 WANDA_SEAT_UNAVAILABLE
```

```python
# cost.py:74-75  最后一道
if cost.unit_cost_fen <= 0 or cost.total_cost_fen != cost.unit_cost_fen * count:
    raise WANDA_COST_UNAVAILABLE
```

**★ 我们 `integrations/wanda/api.py` 里已经有这套解析和判据**（189 项测试里有
"会员价不一致 → 返回 None 不猜"），**但没有任何地方调它**。

## 四、定价：V5 是"一条规则里按渠道分字段"

```python
# v5 domain/quote/models.py:124-137
class PricingRule(BaseModel):
    pricing_enabled: bool = True
    rounding_fen: Literal[1, 10] = 1
    liangpiao_price_mode: Literal['LIMIT','FIXED'] = 'FIXED'
    wanda_pricing:           RoutePricing | None = None   # 万达：fixed_per_ticket
    liangpiao_pricing:       RoutePricing | None = None   # 良票预估价：百分比 + 原价
    liangpiao_fixed_pricing: RoutePricing | None = None   # 良票一口价：百分比 + 成本
    vip_discount_bps: int = 8900                          # 万达会员价折扣
```

```python
# v5 domain/quote/pricing.py:62-65  按渠道 + priceMode 选配置
wanda = is_wanda(cost.provider)
configured = rule.wanda_pricing if wanda else (
    (rule.liangpiao_fixed_pricing or rule.liangpiao_pricing)
    if cost.price_mode == 'FIXED' else rule.liangpiao_pricing
) if cost.provider == 'LIANGPIAO' else None
```

**线上真值**（`business-settings.sqlite3`）：
```json
wanda_pricing      = {"basis":"fixed_per_ticket", 10 档, fixed_add_fen 全是 100}
liangpiao_fixed_pricing = {"basis":"estimated", 10 档, adjustment_bps 1000→100}
liangpiao_price_mode    = "FIXED"
vip_discount_bps        = 8900
```

**我们**：一条规则挂一个 `brands` 列表 + 一套 `tiers`，**没有渠道维度**。

## 五、下单/出票：两套完全不同的接口

| | 良票 | 万达 |
|---|---|---|
| 询价 | `POST /api/v1/order/preflight`（HMAC-SHA256） | 座位图 `real_time_seat.api` + 活动价 `mkt/activity/secret/list.api`（MD5 + 静态 token） |
| 下单 | `ch5_create` → `/api/v1/order/create` | `create_order.api`（走 `preview.py` 的 transport） |
| 查单 | `ch5_order_detail` | `order_status.api` |
| 取消 | `ch5_cancel` | `cancel.api` |
| 会员价 | 无此概念 | `wplusActivity.price` / 内部桥 probe |

**我们 `ticket_flow.py:598` 只调 `self.api.ch5_create(...)`** ——
`self.api` 是 `LiangPiaoAPI`（`build_service` 里写死），**代码里没有按 channel 分支**。

⇒ **万达渠道的单现在会打到良票去下单。**

## 六、要接万达，缺的是这些（按依赖顺序）

| # | 缺什么 | 在哪 | 工作量 |
|---|---|---|---|
| 1 | **认渠道**：从识别结果/hall 名判"这单是不是万达会员场" | `ticket_flow` | 小，但**判据要先和 V5 对齐**（hall 名 vs 别的标志） |
| 2 | **万达成本服务**：座位价 → W+会员价 → 内部桥，三层级联 + 所有硬校验 | `integrations/wanda/` 里加 `cost.py`（我们已有解析层，照 V5 cost.py 补） | 中 |
| 3 | **万达定价**：`wanda_pricing`（`fixed_per_ticket`）+ `vip_discount_bps` | `domain/quote_rules.py` 加渠道维度；`basis=per_ticket` 我已经实现了 | 中 |
| 4 | **万达下单**：`create_order.api` + 内部桥 probe（临时单→读价→取消） | `integrations/wanda/` 加 `preview.py`、`internal_bridge.py` | **大** |
| 5 | **链路分流**：`ticket_flow` 按 channel 走良票或万达 | `ticket_flow.py` | 中，但**改的是下单主链，风险最高** |
| 6 | **出票/发码**：万达出票走 `application/wanda_delivery.py`（已有） | 已存在 | 已有 |

**★ 第 4 条最重**：`internal_bridge` 要**真下临时单**才能拿到会员价 ——
这意味着**测试它就会产生真实订单**（我今天已经踩过一次：真下了 35.89 元的单，你手动取消了）。
