## 二、★ 已修的两处

### 2.1 ★ bubble 33（票速变化）—— **保留文案但已停用**（店主决定）

**同业 B 的场景标签：`票速变化，按新价改价`**，四段话：

```
【影院信息】{city}-{cinema_addr}-{cinema}
---
【购票信息】{movie}-{hall}-{show_time}-{seats}
```
```
【优惠信息】{unit_price}元/张，合计{total_price}元，总优惠{discount}元
```
```
城市、影院、座位数易识别错误，请核对与您的截图是否一致！
```
```
因为距离放映时间较近，更改为快票通道会贵一点，已为您重新报价并改价，请留意
```

**★★★★ 店主明确说：「快速票加价通道我们不需要，可以不设置」。**

**处理方式：停用（不是删掉）**

```python
# templates.py
DISABLED = {
    # 快速票加价通道：店主不需要（2026-10-13）
    "TICKET_MODE_CHANGED",
}

def is_disabled(key): return key in DISABLED

# render_messages 里的硬拦截：
if is_disabled(key):
    raise KeyError(f"模板 {key} 已停用（见 templates.DISABLED）—— "
                   f"店主明确说不做的功能，不许发送")
```

**为什么保留而不是删掉：**
```
① 同业线上预览里有这个码（bubble 33），删了以后对照时会对不上；
② 万一以后要开快票通道，文案是逐字对齐过的，不用重新找。
```

**★ 为什么要有"硬拦截"而不只是"没人调用"：**
```
死代码检查只能发现「现在没人调用」，
发现不了「以后有人顺手调了一条店主明确说不做的功能」。
硬拦截 = 调了就抛，不给静默发送的机会。
★ 两道一起才成立：
    死模板检查  = 发现"没人调用"（维护视角）
    停用守卫    = 保证"调了也发不出去"（安全视角）
```

### 2.2 ★★ `RECOG_FAIL` 拆成分场景变体

**同行 B 里这 7 个码各有各的话，我们原先共用 1 条 + `{fail_reason}`：**

| bubble | 同行 B 的措辞 | 我们的变体 |
|---|---|---|
| 29 | 未识别到您选择的座位信息，辛苦选择一下座位信息截图发我哦 | `seat_missing` |
| 2 | 失败的原因：【{原因}】/ 建议换猫眼小程序的座位截图再发我下~ | （默认） |
| 30 | 此场次已停止购票，建议您选择其他场次截图发送获取报价 / - / 需要距离开场前一小时购买哈 | `show_stopped` |
| 42 | 亲，您选择的场次已开场，无法继续购票，请更换其他场次后重新发送截图~ | `show_started` |
| 43 | 亲，{原因}，请减少座位数量后重新发送截图~ | `seat_limit` |
| 44 | 亲，识别到座位被遮挡，请重新选座后再发送截图~ | `seat_blocked` |
| 32 | 识别失败，{原因}！ | `need_pick` |

**实现方式（不破坏任何现有调用）：**

```python
# 调用方传一个控制键就选到对应文案
out.add("RECOG_FAIL", {"_variant": "show_started",
                       "fail_reason": "您截图的场次已经开场了"})
# ★ 不传 _variant → 回落默认（= bubble 2 的措辞），
#   现有 14 个调用点一行都不用改
```

**已接上的调用点（3 处）：**
```
场次已开场          → show_started
良票没座位（要圈座） → seat_missing
万达座位不在图里    → seat_missing
★ 但 SEAT_UNAVAILABLE（座位被占）不套 seat_missing ——
  那不是"没识别到"，是"识别到了但卖不掉"，说错会让买家白重发一次
```
