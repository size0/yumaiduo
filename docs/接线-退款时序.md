## 一、★ 先说清这组设置管的是哪件事（查了才敢下手）

**上一轮我卡在这里**：退款是良票平台做的、我们拦不住
（`_on_refunded` 是平台告诉我们"退完了"）—— 那 timing 设置还有什么用？

**查完发现关键区别**：
```
退款（钱）= 平台做的，我们拦不住
提交退票申请 = 【我们做的】：
    service.on_refund → flow.on_refund_request → api.ch5_refund
```
**⇒ 这组设置管的是「我们提交申请的那一刻」，不是"钱什么时候到账"。**

**这就说得通了**：
```
weekdays         哪几天提交。不在列表里的日期 ⇒ 不提交，告诉买家等
time_start/end   时段：只在这个时段内提交
delay_seconds    延迟提交：买家申请后先等 N 秒再提交
                 （给买家一个反悔的机会；V5 也有这个行为）
```

## 二、新模块 `application/refund_schedule.py`

```
in_window(cfg, now)      现在能不能提交 → (能不能, 原因)
next_window_hint(cfg)    不在窗口时给买家的一句话
schedule(order_no, ...)  记一条"到点提交"（幂等：重复排不越排越晚）
cancel(order_no)         撤掉一条（买家反悔）
due_now(cfg, now)        到点【且】在窗口里 ⇒ 该提交的那些单
process_due(...)         实际提交（由 handle_run_due 每秒推进）
```

### ★ 四个不猜的取舍

| 取舍 | 做法 | 理由 |
|---|---|---|
| **空 weekdays** | **= 不限制**，不是"七天都不许" | 按"都不许"理解的话，配置一被清空就**永远退不了钱** |
| 坏时间字符串 | 回默认值，判成 bool | 不能让一个手误把设置变成"永远不许" |
| 边界 | **含头含尾**（18:00:00 仍算能提交） | 和人的直觉一致 |
| 延迟提交的推进 | 挂在 `handle_run_due`（**每秒被调一次**） | 复用已有的定时循环，不另造一套 |

**★ 为什么不用命令队列的 `not_before`**：
那是【发给插件的命令】用的。而提交退票是**直接的 HTTP 调用**
（`api.ch5_refund`），不经插件 ⇒ `not_before` 用不上。
⇒ 自己记一个到点时间，由 `handle_run_due` 推进（形状和 `reminders.py` 一样）。

## 三、★ 一个必须处理的真实风险：延迟期间订单可能已经变了

延迟提交是"以后"做的事，而那时：
```
· 买家可能已经反悔（会话没了）
· 订单可能已经退掉了（平台回调先到了）
```
**两种情况都【不能提交】** —— 提交一个不存在的单会拿到 500003，
或者**把已经退掉的单再退一次**。

⇒ `process_due` 提交前**必须核对**：
```python
pending = conv.pending_order
if pending and str(pending.order_no) == order_no:   # 还是那个单
    service.flow.on_refund_request(conv)
```

**★ 而且无论成败都出队**：一直留在队列里会**每秒重试**，那是打自己的接口。
失败靠买家再问一次，而不是无声重试。

## 四、★ 循环依赖又来过一次（1 → 2 → 1）

```
我在 refund_schedule 里写了：
    from application.plugin_runtime import get_local_service
⇒ 成环：plugin_runtime → service → refund_schedule → plugin_runtime
   审计的"循环依赖"从 1 涨到 2。
```

**⇒ 修法和上一轮一样**：**依赖注入** ——
`process_due(service=...)`，由 `plugin_api.handle_run_due` 取好传进去。
```
依赖方向只有【外层 → 内层】，内层不 import 外层。
```

**★ 这已经是同一类问题第二次了**（上一轮是 `ticket_flow` 想 import `plugin_api`
来排队）。**两次的解法完全一样：内层只声明"我需要什么"，由外层喂进来。**

> 我现在的习惯：**在内层写 import 之前，先问"这个模块属于哪一层"。**

## 五、实测

```
默认配置（七天全选 / 全天 / 延迟0）：
    任何时刻 in_window = True        ⇒ 行为一个字不变 ✓
只允许周二周四：
    周二 → True    周三 → False（"今天（周三）不是退款处理日"）  周四 → True
时段 10:00-18:00：
    09:59:59 ✗   10:00:00 ✓（含头）   18:00:00 ✓（含尾）   18:00:01 ✗
空 weekdays + 窄时段：星期判据关掉，时段照常生效 ✓
延迟 30 秒：
    排到 12:00:30、重复排不越排越晚、未到点不捞、到点才捞 ✓
窗口外：不捞，但记录还在（等下一个窗口，不丢）✓
```
