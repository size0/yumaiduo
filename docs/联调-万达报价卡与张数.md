## 〇、先回答两个问题

### 问题 1：为什么没有文案？

**因为你的截图里那两个座位是「未选」状态**，识别返回 `seat: []`：

```json
"rawResults": {
  "isSeatSelection": true, "platform": "猫眼",
  "cinema": "包头九原万达广场店", "hall": "8号激光厅",
  "film": "生化危机：爆发夜", "showtime": "2026-10-14 12:40:00",
  "priceAll": null,
  "seat": [],              ← ★ 空数组
  "seatObstructed": false, "confidence": 0.95
}
```

**良票文档原文：**
```
「截图里没有已选座位（顾客还停在「请先选座」）时 seat 为空数组，
  ★ 这不是错误。」
```

**截图上的证据：** 图例写「灰=可选 / 绿=已选 / 红=已售」，座位上**没有绿色**；
图下方还写着「**请您选择心仪的座位**」。你只是用红笔圈了一下（视觉标注），
但 App 里没真正点选。

### 问题 2：怎么知道是两张？

**★ 就你的这张图而言：我们不知道。** 而且不只是"不知道"，还出了两个问题（见下）。

**★ 有座位时是能数对的**（实测）：

```
识别 seat = [7排12座, 7排13座]
  → 报价卡「座位：7排12座，7排13座」
  → 成本 3400 × 2 = 6800 分
  → 报价「优惠后：35.00元/张，合计：70.00元」   ← 2 张 = 70 元 ✓
    notes: 「万达渠道：2026-10-14 12:40 8号激光厅（W+专享 会员价 34.00 元/座 × 2）」
```

## 一、★★★ 实测发现 3 个真 bug（1 个已修）

### Bug A ✅ 已修：报价卡「原价」恒为 0.00 元

**现场（座位有值的情况）：**
```
原价：0.00元/张，合计：0.00元      ← ★ 应该是 35.90 / 71.80
优惠后：35.00元/张，合计：70.00元
```

**根因：**
```python
def _emit_quote_card(self, result, seats, quote, out):
    origin_unit = _seats_original_fen(result)          # ← 只看识别结果
    ...
    "origin_unit": _fen_to_yuan((origin_unit // n) if origin_unit
                                else (result.price_all_fen // n)),
    "origin_total": _fen_to_yuan(origin_unit or result.price_all_fen or 0),
#   ★ 原价【完全没看 quote】
```

**而万达识别的 `priceAllFen` 实测【从不返回】**（`rawResults.priceAll` 也是 `null`）
⇒ **万达单的报价卡原价恒为 0.00**，买家看到「原价 0.00 / 优惠后 35.00」——
等于在说"原价是零还给你打折"，既不可信，也丢了"便宜了多少"这个说服力。

**修法：** 把成本侧的原价接进来当第三兜底

```python
origin_total = (_seats_original_fen(result)          # ① 截图逐座原价，最准
                or result.price_all_fen              # ② 截图总价
                or getattr(quote, "original_total_fen", None)  # ③ ★ 引擎算的
                or 0)
```

**配套改动：**
```
domain/quote_rules.py
  · QuoteResult 加字段 original_total_fen（默认 0 = 不知道原价）
  · quote() 的三个 return 都带上它
  · ★ 修了我自己注入时误伤的一处：把参数插进了 price_by_tier(...) 调用里
application/ticket_flow.py
  · _emit_quote_card 用上面的三级兜底
```

**修完实测：**
```
原价：35.90元/张，合计：71.80元     ← ★ 对了
优惠后：35.00元/张，合计：70.00元
```
**⇒ 这一单买家看到"原价 71.80，给您 70.00"，我们只赚 2 元（加价 1 元/张）。**

**加了回归断言锁住**（tests/_check_ticket_flow.py）：
```
★★ 原价不再是 0.00（万达没有 priceAllFen）   原价：35.90元/张，合计：71.80元
★★ 优惠后金额不受影响                       优惠后：35.00元/张，合计：70.00元
```

### Bug B ⚠️ 待你定：没选座位时，张数退化成 1

**现场：**
```
座位：（空）                        ← ★ 买家看不到我们按几张报的
原价：0.00元/张，合计：0.00元
优惠后：35.00元/张，合计：35.00元   ← ★ 按【1 张】算的
· notes: 万达渠道：… （W+专享 会员价 34.00 元/座 × 1）
· notes: 买家未指定座位 → 按会员座位区「W+专享」的会员价
```

**根因：**
```python
count = len(seat_names) or int(result.expected_seat_count or 1)
#      └ 没座位 → 0（假值）  └ 识别也没给张数 → None（假值） → ★ 兜底成 1
```
**两个来源都没有时，`count` 静默变成 1。**

**为什么不能随便改：**
```
没选座位时"报几张"有产品分歧：
  ① 先报单价（1 张）+ 让买家说张数 → 现状（但报价卡那张数就是错的）
  ② 先问"要几张"再报价          → 多一轮，但不会报错价
  ③ 按最大可售报                → 买家以为要买那么多，很危险
★ 而且这条只影响【万达 + 没选座位】，良票没座位就直接要截图（`seat_missing`）。
```

### Bug C ⚠️ 待你定：`_resolve_channel` 静默降级 → 万达单被拒

**根因链（这个更值得注意）：**
```
_liangpiao_city_code("包头")
   ↓ 城市表接口一旦失败（抖动/超时）
   except Exception: rows = []
   → code = ""
   ↓
_resolve_channel 返回 None
   ↓
★ 走【良票】分支
   ↓
良票 seats 必填 1~6 → 没座位 → seat_missing
   ↓
买家收到「未识别到您选择的座位信息，辛苦选择一下座位信息截图发我哦」
   而这明明是【万达】单（识别结果里 brandName = 万达影城）
```

**实测复现：** 用假 api（没有 `ch4_city_list`）跑同一张图 → 就是这个结果。
换成真 api（能查到 `包头 → 150200`）→ 正常走万达。

**⇒ 也就是说：城市表接口抖一下，万达单就会掉到良票分支、买家被要求重发截图。**

**修法（我建议的，等你确认）：**
```
识别结果里已经有 brandName = "万达影城" —— 这是【不依赖任何 API】的判据。
当查出品牌是万达、而城市码查不到时：
  · 不该静默降级到良票
  · 应该报一个明确错误（"城市表暂时查不到，稍后重试"）或让 need_human
```
