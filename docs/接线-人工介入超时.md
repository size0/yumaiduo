## 一、★★★ 查出的真 bug：转人工保护从来没生效过

```python
# application/plugin_authorize.py（改前）
def _handed_off(chat_id):
    state = s.conversation.state
    name = getattr(state, "value", None) or str(state or "")
    return "HUMAN" in name.upper()      # ← 判的是【中文显示值】
```

**而 `ConvState.MANUAL` 的 value 是「待人工」** ——
「人工」里没有 HUMAN 这四个字母 ⇒ **永远返回 `False`**。

**它的作用是什么**（`authorize_message_send` 第 110 行）：
```
会话转人工 ⇒ 不允许再发机器人消息
```
**⇒ 这个保护从上线起就没生效过。会话一转人工，
机器人照样往里发消息，和人工客服抢话。**

**★ 这类 bug 的特征**：不报错、不抛异常、测试也不红 ——
**保护静默失效**。只有把"判据到底是什么"拿出来看一眼才发现。

**修法**：判**枚举本身**（`state.name == "MANUAL"`），不判中文显示值。
> **中文是给人看的，随时可能改；拿它当判据，出事只是时间问题。**

## 二、为什么要做「超时关闭」——它是修 bug 的前提

`ConvState.MANUAL` 是**终态**：状态机里所有事件都留在 MANUAL，
**没有任何出口**。所以：
```
不修 bug ⇒ 保护不生效（机器人和人工抢话）
只修 bug ⇒ 会话永远卡在待人工，机器人再也不应答（买家没人理）
修 bug + 做出口 ⇒ 才对
```

**「关闭接管」关的到底是什么**（这个定义很重要）：
```
关的是【机器人要不要闭嘴】，不是会话状态。
会话状态继续停在"待人工"是对的 —— 订单还在人工那边走
（发货、退款都是人在做）。我们要的只是"机器人可以重新应答"。
```
**⇒ `close()` 只清标记，不动 `state`。**

## 三、新模块 `application/manual_control.py`

```
close_after(cfg)        接管多少小时后自动关（0 = 不自动关）
close_statuses(cfg)     订单到了哪些状态就关
should_close(session)   两条判据任一满足
close(session)          关闭接管（只清标记，不动 state）
mark(session)           记下"从这一刻起接管"（幂等）
process_due(service)    由 handle_run_due（每秒）推进
```

### ★ 四个不猜的取舍

| 取舍 | 做法 | 理由 |
|---|---|---|
| **mark 幂等** | 已在接管中**不刷新时间** | 否则买家一直说话就把超时无限往后推，**永远不会关闭** |
| 空 `close_on_status` | **用默认**（不是"一个都不关"） | 配置一被清空就永远关不掉接管 |
| 没有时间依据 | **不关** | 宁可多留一会儿，也不要因为缺字段就让机器人去抢话 |
| `close_after_hours=0` | **不自动关** | 显式关掉这个行为 |

### ★★ 为什么必须加 `manual_since` 字段

原来只有 `Session.updated_at`，而它**每条消息都刷新** ⇒
买家一直说话就永远不超时。**"进入人工的时刻"必须单独记**，
而且要**落盘**（进程重启后不该把"人工正在处理"忘掉 —— 忘了就去抢话）。

**维护点只有一处**：`service._finish()`（所有出口都过它）
```python
if state.name == "MANUAL":  manual_control.mark(session)   # 进人工 ⇒ 记时刻
elif session.manual_since:  session.manual_since = ""      # 离开   ⇒ 清掉
```
> 不在每处转人工的代码里各写一遍 —— **那样早晚漏一处。**

## 四、★ 修审计自己的漏洞（而不是绕过它）

修完之后审计报「孤儿模块 `manual_control`」。**我的第一反应是"再加一个
import 把警告压掉"** —— 但那是**绕开审计，不是在修问题**。

**查了审计的 deps 提取**：
```python
elif isinstance(node, ast.ImportFrom):
    if node.module:                       # ← 只有这一支
        found.add(node.module)
```
**`from . import manual_control` 这种【没有 module】的相对 import
完全不记** ⇒ 用它引用的模块会被误报成孤儿。

**⇒ 修审计**（加一支处理 `node.module is None`）。
修完：孤儿 0，循环依赖仍是 1（没多算出边）。

> **★ 这次我差点犯的错**：为了消一个警告去加一行代码。
> **警告说"没人用"，正确反应是"查它为什么算不出引用"，
> 而不是"再写一行假装有人用"。**

## 五、实测

```
默认配置：超时 1 小时 / 关闭状态 [已发货, 已退款, 交易关闭]

mark：第一次 True、记下时刻；重复 mark False、不刷新时刻 ✓
超时：30 分钟不关、59 分钟不关、61 分钟关 ✓
     超时=0 ⇒ 不自动关 ✓      没有时间依据 ⇒ 不关 ✓
状态：已发货/已退款 ⇒ 关；待出票 ⇒ 不关 ✓
     空列表 ⇒ 用默认（不是"一个都不关"）✓
close：返回 True、标记清空、★ state 仍在「待人工」✓、重复 close False ✓
```

**顺带验证了那个 bug 是真的**：
```
ConvState.MANUAL.value = '待人工'
'HUMAN' in '待人工'.upper()  ⇒  False   ← 原判据必错
```
（这条也写进测试套了 —— 用**真实枚举**验证，不是"看到源码里有 MANUAL 就算过"。）
