## 〇、先回答"第三点"和"要不要做城市映射表"

### 第三点（`seatObstructed`）是什么

**你截图里识别返回的 `rawResults` 有这组字段：**

```json
"seat": [],
"seatObstructed": false,     ← ★ 这个
"confidence": 0.9
```

- `seatObstructed` 直译「**座位被遮挡**」
- 同业文案里有个 bubble 44：`亲，识别到座位被遮挡，请重新选座后再发送截图~`
- **那个码在我们模板里有文案，但没有任何代码会触发它**

**所以第三点的意思是：我怀疑 `seatObstructed` 就是同业那条的判据来源。**

**★ 但良票文档里【完全搜不到这个词】—— 我没有任何证据说明它是什么意思**
（可能是"座位视线被遮挡"，也可能是"截图上的座位被东西挡住、没识别出来"）。

**⇒ 我建议【不接】**：靠一个文档没写、含义靠猜的字段给买家发
"你的座位被遮挡"，猜错就是把买家赶走重截图。
除非你能确认它的含义，或者我们拿一张真被遮挡的图试出来。

### 第二个：**不需要做城市映射表**

**现有的东西够用，缺口不在"表"上。** 链路是这样：

```
识别结果里有 cityName（'娄底'）+ cinemaId（6278）
   ↓
_liangpiao_city_code('娄底')   ← 调良票 ch4_city_list 查城市表
   ↓ 拿到 cityCode = 431300
wanda_lookup(cityId=431300, cinemaId=6278)  ← 出票系统那张 843 条的映射表
   ↓ 拿到 wandaCinemaId = 615
```

**★ 真正的缺口是：`_liangpiao_city_code` 查失败时会【静默返回空】，
然后整单降到【良票分支】—— 而良票 `seats` 必填，没座位号就报 `seat_missing`，
买家收到「未识别到您选择的座位信息」，而他发的明明是万达的图。**

**实测复现：** 用没有 `ch4_city_list` 的假 api 跑一张万达的图 → 就是这个结果。

**⇒ 修法不用建表，用识别结果自带的 `brandName`：**
```
brandName = "万达影城"  ← 不依赖任何接口，不会失败
查不到城市码 + 品牌是万达 → 报 CITY_CODE_UNAVAILABLE（不静默降级）
查不到城市码 + 别的品牌   → 还是正常回落良票（既定设计，别误伤）
```

**★ 一件事我特意【没做】**：我没把「品牌是万达但映射表里没这条」也改成报错。
因为 `mapped=false, NO_MAPPING → 走良票` 是出票系统写明的**正常**语义
（映射表是人工维护的 843 条，新影院还没录进去时本来就该走良票）。
硬报错会让这类单直接卡死。**店主如果要"万达必须走万达"，那是单独的决定，我不在这里偷偷改。**

## 二、④ 影院名截断闸门 —— 已实现

**良票文档 §7.1 原文：**
```
「cinemaTruncated=true（真实样本约四分之一）时 cinemaHitNums 往往大于 1，
  ★ 必须走二次确认。」
```

**实测两张图：**
```
第二张：rawResults.cinema = '万达影城（娄底五江广...'     13 字，以 ... 结尾，true
        ★ 但 cinemaHitNums=1、matchLevel=EXACT
第一张：rawResults.cinema = '万达影城（九原万达广场IMAX店）' 17 字，无 ...，false
```

**★ 关键判断：判据必须是【截断标记】本身，不是候选数。**
```
截断 = 模型只看到了影院名的一部分。
两家不同影院截断后可能长得一样（'万达影城（娄底五江广...'），
平台照样收敛到一家、cinemaHitNums 照样是 1 ——
这种情况我们报出去的价可能是【别家影院】的。
```

**实现：**
```python
# _after_recognition，在 EXACT 放行之前
if result.cinema_truncated and not getattr(conv, "cinema_confirmed", False):
    out.notes.append("★ 影院名被模型截断（cinemaTruncated=true）→ ...")
    return self._ask_candidate(conv, result, out, only="cinema")
```
**配套：**
```
· RecognitionResult 加字段 cinema_truncated（解析 rawResults.cinemaTruncated，
  缺字段默认 False，不误伤）
· _ask_candidate 加 only= 参数（截断时各维度都已有值、pending 为空，
  但仍要强制问一次影院）
· Conversation 加 cinema_confirmed；_apply_pick_event 里置 True
  ⇒ 只问一次，不会死循环
· on_screenshot 里重置 cinema_confirmed
  ⇒ 新截图 = 新识别，上一次的"已确认"不能沿用（否则第二张截断图会被直接报价）
```

**实测：**
```
cinema_truncated=True, can_order_directly=True
  → state = PICK_CINEMA（不是直接报价）
  → notes: ★ 影院名被模型截断（cinemaTruncated=true）→ 按文档要求先让买家确认影院，不直接报价
  → 消息: 亲，识别到多个匹配结果，请确认您要购买的是哪一个：
          1. 万达影城（娄底五江广场XLAND店）（娄底）
          直接回复上面的数字即可完成确认
买家确认过之后再走 → 不再问（防死循环）✓
```

## 三、② 品牌兜底 —— 已实现

```python
brand_is_wanda = "万达" in str(result.brand_name or "")
```
