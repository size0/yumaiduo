# 为什么必须换成"我们自己的插件"（以及 yp_ 令牌为什么会失效）

> 日期：2026-10-14
> 店主：「我需要的是把 V5 的插件完全替换为我们新插件　我们写的不就是一个插件吗」
>
> **店主说得对。** 之前我把 ticket-agent 做成了"**V5 插件 + 我们的后端**"
> 这种一半一半的形态 —— 而那不是我们自己的插件。

---

## 一、我之前做错了什么

```
我之前以为的架构：
  V5 插件(4100) ──转发──▶ 我们的后端(8801) 做判断
                        ↑ 我以为"插件只是手，不需要自己写"

实际应该是：
  我们自己的插件 ──▶ 平台 SDK（直接调平台 API 干活）
       │
       └──▶ 我们的后端（只做业务判断，同机 HTTP）
```

**我把 V5 的插件当成了自己的插件。** 证据：
```
manifest id     = "wanda-seat-autoquote"      ← V5 的插件名
vendor          = "xdl"                       ← V5 的开发者
name            = "万达电影票 AI 客服"          ← V5 的名字
runtime.port    = 4015                        ← 声明和实际(4100)不一致
```
**它甚至还有 `V5_BACKEND_URL` 这个变量名。** 这不是我们的插件。

---

## 二、这个错误直接导致了「连不上插件进程」

### 缺的那一环（对照官方示例）

```javascript
// ★ 官方示例 im-auto-reply/index.mjs:531-532（权威做法）
webhookSecret = data.webhookSecret ?? null;
pluginToken   = data.token ?? null;      // ← 注册换回的新令牌，用它回调核心

// ★ V5 的 server.mjs:27 + :25（我们正在用的）
.then(data => {
  if (data.webhookSecret) cfg.secret = data.webhookSecret;   // 只取了 secret
})                                                            // ← token 被丢掉了
if (process.env.YUMAIDUO_PLUGIN_TOKEN && ...)
  cfg.client = createPluginClient({
    pluginToken: process.env.YUMAIDUO_PLUGIN_TOKEN,   // ← 永远用 env 里那把静态的
  });
```

**⇒ 自注册换回的新 `yp_` 令牌被丢掉了。** 插件永远用启动时 env 里那把。
**⇒ 那把一旦被平台撤销，插件自己永远不会恢复** —— 这正是现在的状况：
```
PluginApiError: 插件令牌无效或已撤销   401 E_UNAUTHORIZED
```

**★ 平台侧那条链路完全正常**（webhook 能进来、入站验签是好的）。
**是我们的插件壳没有实现"注册后使用新令牌"这一步。**

## 三、为什么静态令牌会被撤销（文档 §110-114）

官方指南原文说得很具体：

> **已经有插件在线上跑的开发者请注意**：插件每次进程启动都要自注册一次来换回
> `webhookSecret` 与 `yp_` 令牌，**签署门控对这条路径同样生效**。
> 平台为此设了一个宽限窗口——窗口内已注册过的插件重启照旧放行，
> 但窗口结束后**未签 DPA 的插件一旦重启就会失能**
> （收到 webhook 验不了签、调不了任何接口，**且进程不会退出，你的健康检查大概率发现不了**）。

**逐条对上我们的现状：**
```
· 进程没退出、/healthz 还返回 {"ok":true,"mode":"live"}     ← 对上
· 收到 webhook 验不了签（其实我们验签是好的，用同一把 secret） ← 部分对上
· 调不了任何接口（读店铺 401、改价发货全废）                  ← 完全对上
```

**★ 还有一个更硬的证据**：我们 manifest 申请了
```
im.message.read     ← 属"个人信息类权限"
im.session.read     ← 属"个人信息类权限"
```
文档 §93：**manifest 申请了个人信息类权限时，插件自注册被 403 拒绝**，
除非签了《鱼麦多开发者敏感个人信息处理承诺书》
（**手写签名 + 短信验证码 + 登记数据安全负责人**）。

**⇒ 我判断：`yp_` 失效 = 平台收紧了签署门控，而这几个权限需要承诺书。
这个判断需要你去开发者中心核实**（我看不到你账号的状态）。

## 四、"我们自己的插件"应该长什么样

### 保留：我们的后端（那 3000 行业务逻辑是我们真正的资产）

```
良票建单/改价时序、报价规则、识别报价、二次报价、
退款时序、人工介入、订单拦截、发货…   ← 这些是钱，不能重写
```

### 换成：我们的插件（自注册 + 自己调平台 API）

**从官方示例 `im-auto-reply` 改写**（它正是"IM 入站 → 处理 → 回复"的骨架）。

| 项 | 现在（V5 的） | 应该（我们的） |
|---|---|---|
| manifest id | `wanda-seat-autoquote` | 我们自己的（如 `xdl-ticket-cs`） |
| vendor | `xdl` | 确认入驻登记的 vendor |
| name | 万达电影票 AI 客服 | 我们的名字 |
| 自注册 | `AUTO_REGISTER=false`（用静态令牌） | **`true`，每次启动换新 `yp_`** |
| 注册响应 | 只取 `webhookSecret` | **同时取 `token` 并热替换 client** |
| 业务判断 | 转发给 `V5_BACKEND_URL` | 转发给**我们的后端**（保留） |
| 平台 API 调用 | 插件里已有的 executor | **保留**（那部分本来就是插件该干的） |

**★ 关键认识：插件本来就该自己调平台 API（发消息/改价/发货）——
这部分 V5 的 executor 写得没问题，可以留。
真正缺的是【身份】和【自注册闭环】。**

## 五、动手之前需要你确认的一件事（我做不到）

**去鱼麦多开发者中心看两个状态：**

```
① 「设置 → 协议与签署」：
   · 《鱼麦多开发者数据处理协议》(DPA) 签了吗？
   · 《敏感个人信息处理承诺书》签了吗？
   · 有没有"补签提示"？

② 「我的插件」里 wanda-seat-autoquote 现在的状态：
   · submitted / approved / published / 停用？
```

**为什么必须先问**：
```
· 如果没签承诺书 ⇒ 自注册会 403，我改了代码也换不回令牌，白折腾
· 如果插件被下架/停用 ⇒ 也换不回来
· 如果已签且状态正常 ⇒ 我改完代码就能自己恢复（这是好消息）
```

**★ 还有一件事只有你能做**：签承诺书要**手写签名 + 短信验证码 + 实名认证**。
