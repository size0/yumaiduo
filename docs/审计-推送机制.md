## 一、先把"推送"的方向说清楚（和直觉相反）

直觉上"推送"是**后端主动推给插件**。**实际不是。**

```
插件进程（持有鱼麦多的 platform 客户端）
   │  ① 主动来领：POST /api/v1/commands/claim
   ▼
我们的后端（server.py）
   │  ② 把要执行的命令放在队列里等它来领
   ▲
   │  ③ 插件把买家的消息/订单事件转给后端：POST /api/v1/events
   │
鱼麦多平台 ──webhook──▶ 插件
```

**为什么必须是这个方向**：只有插件持有平台的客户端。
后端**发不了**任何消息 —— 它只能把"请发这句话"排进队列，
等插件来领。

**⇒ 所以"推送通不通"取决于两件事：**
```
① 插件能不能领到命令（claim 链路）
② 插件领到之后，闸门允不允许它真发出去
```

## 二、★★★ 找到的问题：闸门没配 = 买家一个字收不到，而且不报错

`execute-command.mjs` 里 `SEND_MESSAGE` 走的是**默认分支**：

```js
const allowLive = command.type==='SEND_MESSAGE' &&
  (env.LIVE_SEND_GLOBAL_ENABLED==='true' ||
   (command.shop_id===env.LIVE_SEND_ALLOWLIST_ACCOUNT_UNB &&
    command.tenant_id===env.LIVE_SEND_ALLOWLIST_TENANT_ID));
if (cfg.mode==='live' && allowLive)       { 真发 }
else if (cfg.mode==='live' && !allowLive) {
  result = {status:'FAILED',
            provider_result_status:'LIVE_CAPABILITY_GATE_REJECTED', ...};
}
```

**`LIVE_SEND_GLOBAL_ENABLED` 在代码里没有任何默认值** ——
不设就是 `!== 'true'` ⇒ 闸门关着 ⇒ **所有买家消息被拒**。

**★ 为什么这种问题最难查**：
```
命令"成功执行"了 → 回执写回来了 → 队列里那条命令状态是终态
只有 provider_result_status 是 LIVE_CAPABILITY_GATE_REJECTED
⇒ 链路每一环都"没报错"，但买家什么都没收到
```

## 三、★★ 第二个问题：14 个环境变量，仓库里一个说明都没有

插件用 14 个环境变量（`process.env` 读，没有 dotenv 依赖）：

```
YUMAIDUO_COMMAND_MODE        ★ 必填，否则启动就抛错
V5_BACKEND_URL               ★ 不设默认 127.0.0.1:8000（很可能是错的端口）
V5_BACKEND_SECRET_FILE       ★ 密钥交接文件（绝对路径）
LIVE_SEND_GLOBAL_ENABLED     ★★ 不设 = 买家收不到消息
LIVE_SEND_ALLOWLIST_ACCOUNT_UNB / _TENANT_ID   小范围放通用
LIVE_REPRICE_ENABLED         ★ 不设 = 改价一律被拦
CORE_URL                     平台基址
YUMAIDUO_PLUGIN_TOKEN        ★ 两个都要，否则没有官方客户端
YUMAIDUO_TENANT_ID              ⇒ 所有发送命令 OFFICIAL_CLIENT_UNAVAILABLE
YUMAIDUO_AUTO_REGISTER       自注册开关
BASE_URL                     ★ 平台要连它，必须平台可达
PLUGIN_DEVELOPER_TOKEN       注册用
PORT / HOST / V5_BACKEND_TIMEOUT_MS
PLUGIN_EXECUTION_JOURNAL_DIR ★ live 模式必填，否则抛错（故意）
```

而插件目录里**没有 `.env`、没有 `.env.example`、没有部署说明**。
⇒ 新人照代码猜，猜错的第一个后果就是"买家收不到消息"。

## 四、改了什么

### 1. `yumaiduo/plugin-runtime/.env.example`（新增）

14 个变量逐个写清楚：**是什么 / 不设的后果 / 为什么**。

几个关键说明（都是代码里读出来、不是猜的）：
```
· YUMAIDUO_COMMAND_MODE 必须显式设 shadow 或 live，
  否则 server.mjs:18 直接抛 'YUMAIDUO_COMMAND_MODE must be shadow or live'
· LIVE_SEND_GLOBAL_ENABLED 不设 = 买家收不到任何消息（见上面那节）
· live 模式必须给 PLUGIN_EXECUTION_JOURNAL_DIR 的【绝对路径】，
  否则抛 LIVE_EXECUTION_JOURNAL_DIRECTORY_REQUIRED
  —— 这是故意的：真发消息必须有可回查的执行记录
· 密钥【不在这个文件里】。插件自注册拿到 webhookSecret 后
  写到 V5_BACKEND_SECRET_FILE 指向的文件（0600 权限），后端读它验签。
  ⇒ 仓库里不留密钥。
```

### 2. ★★ 插件加「发送能力自检」

```js
export function sendCapability(env) {
  // 逐项检查，并说清"没配会怎样"
  return {mode, can_send, gates, blocked};
}
logSendCapability(sendCapability());     // 启动时打印
```
`/healthz` 也带上：`can_send` / `blocked_gates` / `gates`。

**实测各档配置的输出：**
```
全空                     can_send=false  blocked=[6 项]
只有 mode=shadow          can_send=false  blocked=[5 项]
live 但发送闸门关着         can_send=false  blocked=[LIVE_SEND_GLOBAL_ENABLED,
                                                  LIVE_REPRICE_ENABLED]
用 allowlist 只放通一个店    can_send=true   blocked=[LIVE_REPRICE_ENABLED]
全都开                    can_send=true   blocked=[]
```

**设计取舍：只警告，不抛错。**
```
shadow 模式下闸门本来就该关着 —— 抛错会让人以为插件坏了。
但警告必须说清后果：
  live 模式 → "买家收不到消息，且不会报错"
  shadow   → "当前 mode=shadow，本来就只演练"
```

### 3. 断言（插件这一套从 10 条加到 20 条）

```
★★ 插件有 sendCapability() 自检
★★ 启动时会打印发送能力（配置漏了立刻能看到）
★★ /healthz 暴露 can_send / blocked_gates / gates
★  自检覆盖闸门 LIVE_SEND_GLOBAL_ENABLED / LIVE_REPRICE_ENABLED /
   YUMAIDUO_PLUGIN_TOKEN / YUMAIDUO_TENANT_ID / PLUGIN_EXECUTION_JOURNAL_DIR
★★ SEND_MESSAGE 真受 LIVE_SEND_GLOBAL_ENABLED 管（自检不是摆设）
★★ 插件有 .env.example；覆盖全部关键变量
★★ .env.example 里没有真实密钥（只有占位）
```

★ 最后那条尤其重要：`.env.example` 是**要提交进仓库**的，
它一旦被填上真实密钥就是泄露。

## 五、上线时怎么用这份东西

```
① 复制 .env.example → .env（systemd 用 EnvironmentFile 指向它）
② 先 YUMAIDUO_COMMAND_MODE=shadow 跑一遍
   —— 所有命令返回 WOULD_SEND，不会真发给买家
③ 起插件，看启动日志的 [发送能力] 那几行
   ★ 有 blocked 就先解决，别急着切 live
④ 切 live 之前最少要：
     YUMAIDUO_PLUGIN_TOKEN + YUMAIDUO_TENANT_ID（否则没有官方客户端）
     PLUGIN_EXECUTION_JOURNAL_DIR（live 模式强制要求）
   ★ 发送闸门建议先开 allowlist 一个店，确认无误再开 GLOBAL
⑤ 上线后查 GET /healthz，看 can_send 是不是 true
```

