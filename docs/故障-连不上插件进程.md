# 故障：「连不上插件进程」

> 日期：2026-10-14
> 现象：界面上出现「★ 连不上插件进程」/「读不到店铺」
> 结论：**先是一个配置漏项，修掉之后暴露出真正的根因 —— 插件的平台令牌被撤销了。**

---

## 一、两个独立的问题，叠在一起

### 问题 A：`YUMAIDUO_PLUGIN_URL` 没设（我漏的，已修）

```
插件监听 4100（env 里的 PORT=4100）
代码里的默认值 4015   ← 教学环境的端口
我们的 env 没设 YUMAIDUO_PLUGIN_URL ⇒ 用默认 4015
⇒ 4015 上没有东西 ⇒ Connection refused ⇒ 界面显示「连不上插件进程」
```
**已修**：`ticket-agent.env` 加 `YUMAIDUO_PLUGIN_URL=http://127.0.0.1:4100`。

**★ 这是同机部署必须显式给的一项。** 代码默认值是教学环境的端口，
换一台机器、换一个 `PORT` 就会失效，而症状只是一句人话提示。

### 问题 B：★★★ 插件的平台令牌被撤销（**真正的根因**）

修完 A 之后，错误变成：
```
POST /internal/shops/read  →  HTTP 502  {"error":"OFFICIAL_SHOP_READ_FAILED"}
```
插件把 SDK 的异常吞掉了，所以得直接调 SDK 才看得到真话：
```
ERROR name    = PluginApiError
ERROR message = 插件令牌无效或已撤销
ERROR status  = 401
ERROR code    = E_UNAUTHORIZED
token prefix  = yp_ed2e8…   （静态令牌）
```

**⇒ 插件手里那把 `yp_` 令牌被平台撤销了。**
⇒ 它**调不了任何平台 API**：读店铺、改价、发货、取消、读消息历史…
⇒ 界面上「连不上插件进程」只是最表层的一个症状。

## 二、这条链路的三个环节，各自是否正常

```
  鱼麦多平台  ──webhook──▶  插件(4100)  ──转发──▶  我们的后端(8801)
       │                        │                      │
       │                        │ 用 yp_ 令牌调平台 API  │
       │                        ↓                      │
       │                   ★ 401 E_UNAUTHORIZED        │
```

| 环节 | 状态 | 证据 |
|---|---|---|
| 平台 → 插件（webhook 入站） | ✅ 通 | 公网 POST `/__plugin__/webhook/im.message.received` → 插件回 401 `invalid signature`（正是预期：没签名） |
| 插件 → 我们（转发） | ✅ 通 | 我们已收到 **4563** 条轮询请求（claim / run-due / auto-run / recovery） |
| 插件 → 平台（出站 API） | ❌ **401 令牌被撤销** | 直接调 SDK 得到 `插件令牌无效或已撤销` |

**★ 注意一个反直觉的点**：webhook **入站**不需要那把 `yp_` 令牌
（入站靠的是 `webhookSecret` 验签，那个是好的）。
所以"消息能收进来"和"插件能干活"是**两条独立的路**，
前者正常**不能**说明后者正常。

## 三、还没验证的一件事（诚实说）

`/api/v1/events` 的请求数是 **0** ——
说明**切换之后一条真实买家消息都还没进来过**。
所以"买家消息能不能被正确处理"这条路，**目前还没有真实证据**，
只有链路的静态检查（入口可达、验签在工作）。

## 四、怎么修

### 唯一的修法：让插件重新拿到一把有效的平台令牌

**这个我做不了** —— 令牌是平台颁发的。两条路：

**路 A：找鱼麦多重新颁发（推荐先问）**
```
问清三件事：
  ① 这把 yp_ed2e8… 是谁、什么时候撤销的、为什么
  ② 插件现在是什么状态（是不是被停用/下架/欠费）
  ③ 怎么重新发一把（后台自助，还是找他们）
★ 平台才是真相来源。"令牌无效"有很多种原因，
  盲换一把可能立刻又被撤销，白折腾。
```

**路 B：用 PLUGIN_DEVELOPER_TOKEN 自注册换新令牌**
```
插件已支持：YUMAIDUO_AUTO_REGISTER=true + CORE_URL + PLUGIN_DEVELOPER_TOKEN + BASE_URL
            ⇒ 它 POST /api/v1/plugin/runtime/register 换回新令牌
★ 代价与风险：
  · 会重新走一遍注册 ⇒ 可能换掉 pluginId / baseUrl 登记
  · 旧的 yp_ 如果被撤销是因为"插件被下架"，换了也没用
  · 注册返回的 webhookSecret 会变 ⇒ 我们这边必须同步，
    否则验签全失败（插件会写交接文件，但需要配 V5_BACKEND_SECRET_FILE）
  ⇒ 这个动作要你确认后再做，因为它碰的是线上注册状态。
```

## 五、这次教我的事

```
① 「同机部署」不等于「地址自动对」。端口是环境给的，
   代码里的默认值只是某一台机器的值。跨机器部署必须核对每一项地址。
   ⇒ 我有核对密钥，却没核对插件地址 —— 只核对了"我以为会错的那一项"。

② 中间层吞异常会让根因完全不可见。
   插件把 SDK 的 401 变成了 502 OFFICIAL_SHOP_READ_FAILED，
   界面又把它变成一句「连不上插件进程」。
   ⇒ 排查时要【跳过中间层直接问最底层的那个】，三层转述之后信息就没了。

③ 「入站通」不等于「出站通」，但症状长得像。
   webhook 能进来（验签密钥是好的）让人以为插件"活着"，
   而它其实一个平台 API 都调不动。
```
