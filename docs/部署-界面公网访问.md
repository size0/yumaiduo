# 界面访问：https://wd.xdw0.cn/ta/

> 日期：2026-10-14
> 起因：店主问「为什么 V5 的可以用 https://wd.xdw0.cn/v5/ui 打开？」

---

## 一、先回答那个问题：V5 的为什么能开

**因为它的界面挂在 `/ui/` 前缀下，而 nginx 有一条路把它反代出去。**

```
nginx:  location ^~ /v5/ui/  →  proxy_pass http://127.0.0.1:4100/ui/
                                                         ↑ 插件的 PORT
插件 ui.mjs:  if (path !== '/ui' && !path.startsWith('/ui/')) return false;
              fetch(new URL(path, backendUrl))   ← 把 /ui/* 【原样】转给后端
V5 后端:      它的页面就挂在 /ui/ 下
```

★ **关键**：`ui.mjs` 是**原样转发**（不剥前缀）。所以后端必须自己认得 `/ui/`。
**我们的后端原来挂在根路径** ⇒ 转发过来是 `/ui/orders` ⇒ 我们 404。

## 二、现在的访问方式

```
https://wd.xdw0.cn/ta/            AI助理
https://wd.xdw0.cn/ta/features    功能设置 ← 良票凭证在这里填
https://wd.xdw0.cn/ta/replies     回复文案
https://wd.xdw0.cn/ta/qa          关键词回复
https://wd.xdw0.cn/ta/rules       报价规则
https://wd.xdw0.cn/ta/quotes      报价记录
https://wd.xdw0.cn/ta/orders      订单管理
https://wd.xdw0.cn/ta/shops       店铺管理
```

**为什么是 `/ta/` 而不是 `/ui/`**：这台机器上 `/ui/` 已经被别的系统占了
（nginx 的 `location ^~ /ui/` → 4003，是 ticket-system 的门户）。

**为什么不用 `/v5/ui/`**：那条路经插件的 `ui.mjs`，而它有一份 **API 白名单**：
```javascript
['/ui/api/settings', '/ui/api/shops', '/ui/api/quotes', '/ui/api/orders', ...]
```
我们的 `/api/qa`、`/api/rules`、`/api/templates` 不在名单里 ⇒ 会被回 405。
⇒ **直接反代到我们自己的 8801**，前后端一起过去，行为可预测。

---

## 三、做法（两半，缺一不可）

### ① 服务端：认得前缀

`server.py`：
```python
PREFIXES = ("/ui", "/ta")        # ★ 集中在这里，加前缀只改这一行

def _strip_prefix(path):
    """/ta/orders -> /orders。只剥前缀，不重写路由（保证只有一套实现）。"""

def _base_for(path):
    """这次请求该用哪个 base（注入 HTML）。"""
```
三个入口（GET/PUT/POST）都先 `path = _strip_prefix(path)`。
**HTML 响应里注入两样**：
```html
<base href="/ta/">                            ← 管【相对】路径（style.css）
<script>window.__DSH_BASE__='/ta/';</script>   ← 管【绝对】路径（fetch）
```

### ② 前端：知道自己在哪个前缀下

- **HTML 里的资源/导航改成相对路径**（107 处）：
  `href="/style.css"` → `href="style.css"`，`href="/orders"` → `href="orders"`
  ★ `<base>` **只管相对路径**，根绝对路径（`/x`）它管不了。
    这就是第一版没生效的原因：`/config.css` 被解析到域名根，
    被 nginx 的 `location /`（别的系统的 SPA）接管。
- **JS 的 API 调用加前缀**：
  ```javascript
  window.withBase = p => p.charAt(0) === '/'
      ? window.__dshBase.replace(/\/$/, '') + p : p;
  await fetch(window.withBase('/api/settings'))
  ```
  ★ 挂在 `window` 上而不是 `const BASE` ——
    一个页面会加载多个 JS，各自 `const BASE` 会撞成
    `Identifier 'BASE' has already been declared`，而且第二个文件
    **整段不执行**（运行时才炸，`node --check` 看不出来）。

### ③ nginx

```nginx
# ★ 注意【没有尾斜杠】：
#   尾斜杠会让 nginx 把 /ta/ 前缀替换掉 ⇒ 后端收到 /orders
#   ⇒ 它算不出该注入 <base href="/ta/"> ⇒ css/js 和 /api/* 全打到根路径。
location = /ta { return 302 /ta/; }
location ^~ /ta/ {
    proxy_pass http://127.0.0.1:8801;
    ...
}
```

## 四、★★★ 这次踩的四个坑（都是"看着成功了其实没有"）

### ① 备份文件留在了生效目录里

我改 nginx 前备份成 `sites-enabled/wd.xdw0.cn.bak-before-ta`。
而 `nginx.conf` 是 `include /etc/nginx/sites-enabled/*` —— **通配符把备份也加载了**。
⇒ 生效配置里出现 **4 个** `server_name wd.xdw0.cn`
⇒ Nginx 用**加载顺序最后**的那个 block ⇒ **是备份（加 /ta/ 之前的旧版本）在服务**。
⇒ 我的 /ta/ 配置怎么写都不生效。

**修**：备份挪到 `/etc/nginx/backups/`。
**教训**：备份要放在**不会被通配加载**的地方。

### ② 中文注释把下一行指令吞了

我用 python 拼配置，一段中文注释和 `location = /ta { ... }` **并到了同一行**：
```
# <base href="/ta/"> …走对。    location = /ta { return 302 /ta/; }
                              ↑ 整行被当成注释，指令消失
```
**后果**：`location ^~ /ta/ { ... }` 悬空，`/ta/` 落到别的 location。
**而 `nginx -t` 说"成功"、`curl` 说 200** —— 因为 200 是**别人家**的页面。

**★★ 教训**：`200 但不是我的内容` 比 `404` 危险得多。
**判据必须是"标题/内容对不对"，不是"状态码是不是 200"。**
（我后来就是靠对比 `<title>` 才发现的。）

### ③ 我加了个专属响应头来定位，才发现 location 没生效

连续几轮我都在"猜哪个 server/location 生效"，而各种表象都能被别的块伪造。
最后给 `/ta/` 加 `add_header X-Ticket-Agent`，
**看到头 = 这条路真的通了；看不到 = 被别的块接管**。
⇒ 排查配置问题时，**加一个有区分度的标记**比反复看状态码有效。

### ④ 我的正则把闭合引号吞了

改 HTML 路径的正则写错，导致 107 处全部变成 `href="style.css""`（多一个引号）。
**形状唯一**（`=""`），所以能精确修回来。

## 六、回滚

```bash
# nginx
sudo cp /etc/nginx/backups/wd.xdw0.cn.bak-before-ta \
        /etc/nginx/sites-enabled/wd.xdw0.cn
sudo nginx -t && sudo systemctl reload nginx

# 后端（如果有问题）
sudo systemctl stop ticket-agent
```
★ 我们只绑 `127.0.0.1:8801`，即使 nginx 出问题也**不影响插件那条链路**
（插件直连 8801，不经过 nginx）。
