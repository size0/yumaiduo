## 三、两个实现细节，请你在解析时注意

1. **`wandaCinemaName` 不一定含"万达"**。用例 2 的万达侧规范名是
   `儒意影城(CBD万达广场店)原万达影城` —— 影院改名过，但 ID 仍是万达体系的 `595`。
   **请只用 ID，不要用名字做校验或二次匹配**（名字字段只给日志/排查用）。

2. **`sourceCinemaName` 可能为空串**。它来自 `cinema_identity` 表，查不到就是 `""`；
   `mapped`/`wandaCityId`/`wandaCinemaId` 不受影响，不要因为名字为空就判定失败。

其余按你的要求执行：

| 你的要求 | 实现 |
|---|---|
| 只读、`?mode=ro`、不建表不写不迁移 | ✅ `sqlite3.connect("file:…?mode=ro", uri=True)`；单测断言不留 `-wal`/`-shm` 且主库字节不变 |
| 连不上不抛 500 | ✅ 降级为 `IDENTITY_STORE_UNAVAILABLE`（含：库不存在 / 不是数据库 / 不可读） |
| 不做长期缓存（≤60s TTL 或每次读） | ✅ **完全不缓存**，每次请求读库（单条主键查询，微秒级） |
| 不整表返回 | ✅ 只返回单条 |

### ★ 一个必须注意的上游行为：`showDate` 参数**不生效**

上游（万达 `ticket-api`）**忽略** `showDate`，返回的是**它的当前开放日期范围**。
本次会话里我实测到它随当天日期滑动：

| 实测时间 | 请求 showDate | 实际返回的日期 |
|---|---|---|
| 10-09 | 10-09 / 10-10 / 10-11 | 三次都返回同一份（10-09/10/11/16/17…） |
| 10-13 | 2026-10-13 与 2026-10-11 | 都返回 **10-13 ~ 10-18**（10-11 已过去，故为空） |

**所以你必须自己按 `showtimeFilmDateInf[].date` 过滤**（格式 `YYYYMMDD` 整数），
不要假设请求里传的日期等于返回的日期 —— 否则会拿到一堆别天的场次，
或者像我用例里那样"以为接口坏了"。

返回结构（和之前一致）：
```
data.showtimeFilmInf[]                      ← 影片
  ├ filmId / extFilmId
  └ showtimeFilmDateInf[]
      ├ date                                ← ★ 用它过滤
      └ showtimesInf.showtimeList[]
          ├ showtimeId                      ← ★ 你要的
          ├ realtime                        ← 开场毫秒时间戳
          ├ hallName / salesPrice / areaPriceList[]
          └ filmList[0]{filmName, version, versionLanguage, duration}
```
