> 日期：2026-10-14
> 店主：「关键词回复中的设置为知识库能不能行，agent 根据这些来回复
> 　　　　要不然现在 agent 起到什么作用
> 　　　　我看你很多关键词都配置了同样的话术」

## 一、先回答：这个功能**其实已经存在了**

我核实过，不是"要不要做"，是"早就做了但没做通"：

```
service.py:644  _faq_lookup()      ← 查的就是关键词回复那份数据
service.py:457  tools_for(conv, faq_lookup=_faq_lookup)
agent.py:820    提示词：「一律先调 search_faq，然后照查到的那句说」
agent.py:836    「唯一能直接说「可以」的，是 search_faq 查到的口径」
```

**而且已经区分了两种用法**（代码注释里写着）：
```
关键词回复：买家原话【精确命中】关键字才回 —— 逐字可控
FAQ 工具  ：模型拿关键词来【查】—— 允许模糊
```

### 那为什么感觉 agent 没起作用？

**因为知识库里的关键字是编号，不是问题。**

第 5 条（999）是一份完整的 FAQ 索引：
```
亲，以下为常见问题，请自行寻找答案
1、如何购票？  回复"001"
2、支付后多久出票？ 回复"002"
3、可以改签和退票吗？回复"003"
4、票出错了咋办？回复"004"
5、取票码用不了咋办？回复"005"
```
而 agent 的 `search_faq` 是**按关键字子串匹配** ——
买家常问「多久能出票」，命不中关键字是「002」的那条 ⇒ **查不到**。
⇒ 模型只能自己编，或者转人工。

**★ 所以：知识库存在，但它只服务于"买家回复编号"这条路，agent 用不上。**

## 三、做了什么

### 1. 给每条规则加「买家会怎么问」

```python
@dataclass
class QARule:
    ...
    # ★★ 「买家会怎么问」的同义问句
    #   用途【只有一个】：给 agent 的 search_faq 做检索
    #   ★ 它【不】影响 match()（那条路是"逐字可控"）
    questions: list = field(default_factory=list)
```

例（002 那条）：
```python
questions=["支付后多久出票", "付款后多久出票", "多久发货",
           "出票失败怎么办", "会不会不出票"]
```

**16 条知识类规则都补了问句**（社交应答「好的/谢谢/稍等」不补 ——
买家不会去"问"谢谢，那是硬凑）。

### 2. `_faq_lookup` 改成「问句优先，关键字兜底」

**顺序很重要（我踩了坑）**：
```
原来第一步是 qa.reply(kw)，而它是【子串匹配】⇒
  「取票码用不了怎么办」含「取票」⇒ 立刻返回 014（怎么取票）
  「出票失败怎么办」含「出票」⇒ 立刻返回 002（出票时长）
  ⇒ 特意为这两个问题写的 005 / 011 永远没机会。
```
**正确优先级：具体压笼统。**
```
① 问句精确相等 / 整句包含      ← 特意写的，最准
② 问句模糊（按【覆盖了多少字】打分 + 最长公共子串兜底）
③ 关键字精确相等
④ 关键字子串匹配                ← 原来的行为，兜底（按编号查"002"照旧能用）
```

★ 打分的口径是"覆盖了问句的多少字"，不是"问句多长"——
笼统的问句可以很长，但只覆盖一点点。

### 3. 实测：改前全查不到，改后 18 个都查得到

```
多久能出票 / 多久出票          → 出票时间1-30分钟
取票码用不了怎么办 / 取票码无效   → 换人工、录音、凭录音退款
扫码取不出票                  → 同上（不会被"出票"抢走）
怎么取票 / 取票码在哪          → 自助取票机扫码
可以改签吗 / 能退票吗          → 兑换券失效，不能退改
票出错了怎么办 / 座位不对       → 座位号与原座不一致的处理
怎么买票 / 购买流程            → 完整流程
出票失败了 / 出票失败怎么办     → 已自动退款
怎么付款                     → 点击右上角立即购买
常见问题 / 有哪些问题          → FAQ 索引
会员座能买吗 / 灰色能买吗      → 可以买
这个可以买吗 / 能买吗          → 发选座图
```

**唯一查不到的：「能开发票吗」** —— 知识库里确实没有这条。
**这是要你补的内容**，不是 bug。

## 五、新测试套 `_check_knowledge.py`（11 项）

```
一、知识库结构
   规则表非空 / 每条有 id 和内容
   ★★ 每条【知识类】规则都有「买家会怎么问」（否则 agent 查不到）
   ★  社交应答类没有被硬凑问句
   ★  同义问句不重复（重复会让口径打架）
二、一个条目多个关键字
   ★★ 合并条里的每个关键字都还能被 match() 命中
   ★  每个关键字都能回出话
三、agent 查得到吗
   ★★ 每条规则至少有一个问句能查到
   ★★ 具体问句压过笼统关键字（顺序不能反）
四、match() 老行为没变（逐字可控那条路）
   ★★ 谢谢 / 999 / 002 的回法没变
```

**★ 其中一条断言我自己收了两次**：
第一版要求**所有**规则都有问句，结果「好的/谢谢/稍等」挂了 ——
后来想清楚它们是**社交应答不是知识**，改成"只要求知识类，
但例外要显式登记"（`SOCIAL = {"好的","谢谢","稍等"}`），
这样新增规则忘写问句还是会被抓住。
