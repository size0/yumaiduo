# 插件与后端：方向、密钥、谁调谁

> 这份文档解决一个很容易搞混的问题：**"插件"到底调谁？**
>
> ★ 写成文档是因为我（AI）一开始就把它说错了 ——
>   把"插件和我们"的密钥说成了"插件和鱼麦多"，方向也搞混了。

---

## 一、先搞清角色：三方，不是两方

```
┌─────────────┐
│   鱼麦多    │  闲鱼店铺的运营平台
│  （平台）   │  提供 SDK + 网页回调（webhook）
└──────┬──────┘
       │ ① 推事件（买家消息/订单变化）
       │    带签名 x-yumaiduo-signature
       ↓
┌─────────────┐
│   插件      │  ★ 跑在【卖家的店铺环境】里
│（执行器）   │    源码：yumaiduo/plugin-runtime/
│             │    ★ 它是 V5 的一个独立组件（见下面「替换范围」）
└──────┬──────┘
       │ ② 转发事件给我们（同一把密钥签名）
       │ ③ 领命令、报结果
       ↓
┌─────────────┐
│   我们的后端│  ★ 这部分是 ticket-agent 自己写的
│（大脑）     │    server.py + application/plugin_api.py
│             │    http://127.0.0.1:8801
└─────────────┘
```

### ★ 替换范围（ticket-agent 替掉 V5 的哪些组件）

线上 V5 是**两个组件**，都要替：

| V5 组件 | 线上位置 | 我们的对应物 | 状态 |
|---|---|---|---|
| **V5 后端**（FastAPI 大脑） | `/opt/ticket-system-v5/backend/` | `server.py` + `application/` | 自己写 |
| **V5 插件**（店铺里的执行器） | `/opt/ticket-system-v5/plugin-runtime/`<br>包名 `v5-yumaiduo-plugin-runtime` `0.2.0-rc.1`<br>`ExecStart=node src/server.mjs` | `yumaiduo/plugin-runtime/` | 拷自 V5（见 `PROVENANCE.md`） |

**两者通过 HTTP 对接**：插件来 `claim` 领命令、来 `/result` 报结果。

> ★ 线上还有**另一个**插件 `@xdl/wanda-seat-autoquote`（`2.2.50`，
>   跑在 `/opt/wanda-seat-autoquote/current/`，自带 UI 和出票工作台）。
>   它和 `plugin-runtime` 不是一个东西 —— 排查时别搞混。
>   那份的链路见 `docs/发货链路.md`。

**★ 关键认识：插件是"手"，我们是"脑"。**

```
插件会做的：发消息、改价、发货、取消、读订单 —— 都是【动手】的活
插件不会做的：决定该发什么、该不该改价 —— 那是【判断】，在我们这边

⇒ 所以插件每隔几秒来问我们："有没有要我做的？"（claim）
   我们把要做的事写成【命令】存着，它来领
```

## 二、两个方向，各自的密钥

### 方向 ①：鱼麦多 → 插件（插件验签）

```
鱼麦多把买家消息推给插件：
    POST 到插件的 /__plugin__/webhook
    带请求头 x-yumaiduo-timestamp / x-yumaiduo-signature

插件自己算一遍（server.mjs:16 的 verify()）：
    对得上才处理 —— 否则任何人都能让插件去发消息

用的密钥：YUMAIDUO_WEBHOOK_SECRET（卖家在鱼麦多后台配的"网页回调密钥"）
```

### 方向 ②：插件 → 我们（我们验签）

```
插件把收到的事件转发给我们：
    POST 到 /api/v1/events
    带请求头 x-yumaiduo-timestamp / x-yumaiduo-signature

我们算一遍（integrations/yumaiduo/signature.py）：
    对得上才处理 —— 否则任何人都能伪造买家消息让系统下单

用的密钥：★★ 和方向 ①【是同一把】
    插件源码 backend-request.mjs:9：
        createHmac('sha256', secret()).update(`${timestamp}.${raw}`)
    而 secret 来自 cfg.secret = process.env.YUMAIDUO_WEBHOOK_SECRET
```

### 所以

```
一把密钥，管两个方向：
    鱼麦多签名给插件 → 插件验
    插件签名给我们   → 我们验
⇒ 我们能确认：这个请求真的来自【装了这把密钥的那个插件】
   密钥只有卖家和插件知道 ⇒ 别人伪造不了
```

### 方向 ③：插件 → 鱼麦多（发消息/改价/发货）

```
插件执行命令时调鱼麦多的 SDK：
    client.im.sendMessage(...)       发消息
    client.im.sendImage(...)         发图
    client.orders.changePrice(...)   改价
    client.orders.fakeShip(...)      发货
    client.orders.cancel(...)        取消
    client.products.polishAll(...)   抛商品

用的凭证：【鱼麦多发的那套 SDK 凭证】
    插件装进店铺时平台给的（YUMAIDUO_PLUGIN_TOKEN / YUMAIDUO_TENANT_ID 等）

★ 和方向 ①② 的密钥【完全无关】。
  我一开始就是把这两个说混了。
```

## 三、完整往返（一次买家消息）

```
① 买家在闲鱼发消息
        ↓
② 鱼麦多推事件给插件（签名 A，插件验）
        ↓
③ 插件转发给我们 POST /api/v1/events（签名 A，我们验）
        ↓
④ 我们存下事件（按 event_key 去重）
        ↓
⑤ 插件每秒催我们：POST /api/v1/events/run-due
        ↓
⑥ 我们处理事件 → 走完整编排（识别/报价/状态机）
   → 生成命令（比如 SEND_MESSAGE "在的哈~ 把选座截图发我看下就行"）
        ↓
⑦ 插件来领：POST /api/v1/commands/claim（签名 A，我们验）
   → 拿到 {commands: [{type, text, shop_id, history_message_ids, ...}]}
        ↓
⑧ 插件用鱼麦多 SDK 把这句话发出去（SDK 凭证）
        ↓
⑨ 插件回报结果：POST /api/v1/commands/{id}/result（签名 A，我们验）
   → 我们记 status=SENT + sent_message_id
```

## 四、为什么密钥必须验（不验会怎样）

我们这三个端点各有能力，被人拿到就等于出事：

| 端点 | 被伪造的后果 |
|---|---|
| `/api/v1/events` | 伪造买家消息 → **让系统照着假消息下单** |
| `/api/v1/commands/claim` | 领走命令 → **真插件领不到，消息发不出去** |
| `/api/v1/commands/{id}/result` | 伪造回执 → **把没发的消息标成已发** |

**验签的两个要点：**

```
① 签名要对【原始字节】算，不能对"解析后再序列化"算
   JSON 键序/空格往返会变 → 合法请求会被判成伪造
   ⇒ 所以 server.py 用 _read_raw() 而不是 _read_body()

② 时间戳要卡窗口（我们卡 5 分钟）
   不卡的话，一个抓到的旧请求可以永远重放
```

## 五、我在文档里写错过的地方（留个记录）

| 我原来写的 | 实际 |
|---|---|
| "插件通信密钥"泛指 | 它是**鱼麦多网页回调密钥**（`YUMAIDUO_WEBHOOK_SECRET`），卖家在鱼麦多后台配的那把 |
| 说成"插件 ↔ 我们"专用 | **一把管两个方向**：鱼麦多→插件、插件→我们 |
| 没说清插件调鱼麦多用什么 | 用**鱼麦多 SDK 凭证**（装插件时平台给的），与此密钥无关 |
| **"插件不是我们写的"** | ★★ **说错了**。插件是 V5 的独立组件，**同样归 ticket-agent 替换**；<br>只是它的源码是**从 V5 拷来的**（有授权，见 `PROVENANCE.md`），<br>不是从零写 —— 但"拷来用"和"不归我们管"是两件事。 |
| 以为"V5 不需要密钥" | V5 **需要**（`main.py:924/989/996`）。<br>只是**没配也能启动**，后果是 run-due 回 401 → 插件领不到活 → 静默不工作。 |

**★ 我搞混的根源**：线上有**两个**插件，我只看了自己拷的那一个就当成了全部：

```
/opt/ticket-system-v5/plugin-runtime/  ← 我拷的（bridge，src/server.mjs）
/opt/wanda-seat-autoquote/current/     ← 另一个（自带 UI，index.mjs）
两个都在跑（ticket-system-v5-plugin.service / wanda-seat-autoquote.service）
```
