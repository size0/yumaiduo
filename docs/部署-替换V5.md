# 用 ticket-agent 替换 V5：步骤与回滚

> 日期：2026-10-14
> 店主：「把 v5 替换掉」
> **★ 这是生产变更。这份文档先立法：每一步都要能单独回滚。**

---

## 一、★★ 先把机制说清（这决定了替换有多难）

我查了插件源码，**替换比听起来简单**：

```
鱼麦多 ──webhook──▶ 插件（BASE_URL 是【插件自报】的回调地址）
                        │
                        │ 插件去哪里拿"该做什么"
                        ↓
                 V5_BACKEND_URL   ← ★★ 替换就是换这一个环境变量
                        │
        ┌───────────────┴───────────────┐
        ↓                               ↓
  V5 后端（FastAPI，:8101）      我们的后端（:8801）
```

**★ 关键结论**：
```
· 插件不用换 —— 我们的 yumaiduo/plugin-runtime/ 就是从 V5 拷来的同一个包
· 平台不用重新注册 —— BASE_URL 不变（还是插件的地址）
· 要换的只是插件的一个环境变量：V5_BACKEND_URL
· ⇒ 回滚 = 把这个变量改回去 + 重启插件（30 秒的事）
```

**⚠️ 但同时只能有一个"脑子"**：插件的 `backendUrl` 只能指一个地址。
所以**不能"两个后端同时服务同一个店铺"** —— 那会让两个脑子对同一批买家
各说各话、各改各的价。

## 二、★ 三个阶段（每个阶段都能停下来）

### 阶段 0：准备（不改任何线上行为）

```bash
# 在 V5 那台机器上（插件所在机器，插件才连得到 127.0.0.1）
# ★ 必须是同机：插件默认 backendUrl = http://127.0.0.1:8000
sudo mkdir -p /opt/ticket-agent
sudo chown ubuntu:ubuntu /opt/ticket-agent

# 把 ticket-agent 拷上去（排除本地数据与缓存）
rsync -av --exclude '__pycache__' --exclude '.git' \
      --exclude 'data/*.sqlite3' --exclude 'data/sessions.json' \
      ./ticket-agent/ ubuntu@<host>:/opt/ticket-agent/
```

**⚠️ 端口**：V5 后端占 `8101`，我们默认 `8801` ⇒ **不冲突，不用改**。

### 阶段 1：★ 影子跑（receives 真事件，但不发任何东西）

```bash
# 插件侧：把脑子指向我们，并把模式降到 shadow
sudo sed -i 's|^V5_BACKEND_URL=.*|V5_BACKEND_URL=http://127.0.0.1:8801|' /etc/ticket-system-v5/plugin.env
sudo sed -i 's|^YUMAIDUO_COMMAND_MODE=.*|YUMAIDUO_COMMAND_MODE=shadow|' /etc/ticket-system-v5/plugin.env
sudo systemctl restart ticket-system-v5-plugin
```

**★ 为什么这一步安全**：插件的每个"动手"命令都有一道闸
```javascript
// failed-order-close.mjs / order-engagement.mjs / product-polish.mjs
if (cfg.mode !== 'live') return {status:'WOULD_SEND'};
// execute-command.mjs 第 30 行：只有 live 且 allowLive 才真的发
```
⇒ **shadow 下插件只"演练"，买家一个字都收不到。**

**这时候要验的**：
```
① 我们的后端确实在收事件（看日志）
② 我们生成的命令【和 V5 当时的判断一致】（这是重点）
③ 没有 500 / 验签失败 / 身份缺失
```

### 阶段 2：切 live（真的开始干活）

```bash
sudo sed -i 's|^YUMAIDUO_COMMAND_MODE=.*|YUMAIDUO_COMMAND_MODE=live|' /etc/ticket-system-v5/plugin.env
sudo systemctl restart ticket-system-v5-plugin
```

**⚠️ 切之前必须确认这几条**（缺一条都别切）：
```
□ data/liangpiao.json 已配好（良票 app_key/app_secret/tel + 模型 key）
□ 插件密钥已就绪（V5_BACKEND_SECRET_FILE 指向插件的交接文件）
□ LIVE_SEND_GLOBAL_ENABLED / 允许名单已设（否则 SEND_MESSAGE 静默不发）
□ PLUGIN_EXECUTION_JOURNAL_DIR 是【绝对路径】（live 模式强制要求）
□ 报价规则已导入（否则每单都走兜底报价）
```

### 阶段 3：观察与回滚

```bash
# 回滚（30 秒）
sudo sed -i 's|^V5_BACKEND_URL=.*|V5_BACKEND_URL=http://127.0.0.1:8101|' /etc/ticket-system-v5/plugin.env
sudo sed -i 's|^YUMAIDUO_COMMAND_MODE=.*|YUMAIDUO_COMMAND_MODE=live|' /etc/ticket-system-v5/plugin.env
sudo systemctl restart ticket-system-v5-plugin
```

**★ V5 后端【不要停】** —— 留着它，回滚才有意义。
（它不吃资源；而且它跑着的时候我们和它不冲突，因为只有一个脑子在接线。）

## 三、★★★ 动手之前必须先解决的三件事

### ① 人类页面的鉴权 —— ✅ **已完成**（2026-10-14）

**原来的问题**：
```
插件端点有验签（server.py 的 _plugin_api）✓
但 /api/settings、/api/orders、/api/quotes… 【一道闸都没有】
```
绑 `127.0.0.1` 时还好，一旦对外绑定就整个后台裸奔。

**现在做了**：
```
TICKET_AGENT_HOST=0.0.0.0 ⇒ 自动打开 Basic Auth（★ 忘了加也不会裸奔）
TICKET_AGENT_HOST=127.0.0.1（默认）⇒ 不开，本机开发不受影响
TICKET_AGENT_USER=admin         用户名
TICKET_AGENT_PASSWORD=…         密码
TICKET_AGENT_AUTH=on|off        显式覆盖自动判断

★ 对外绑定但【没设密码】⇒ 拒绝启动（退出码 2）
  —— 宁可起不来，也不留一个没密码的公开后台
★ /api/v1/* 豁免（插件端点，它有自己的验签，而且不带 Basic 头）
★ 密码用 hmac.compare_digest 比（不用 ==，避免时间侧信道泄露前缀）
★ 401 带 WWW-Authenticate ⇒ 浏览器弹登录框，不是一个看不懂的错误
```

**实测**（起真服务打真请求）：
```
无凭据 /api/settings → 401     错密码 → 401     对密码 → 200
页面   /             → 401     插件端点 /api/v1/… → 404（不是 401，没被鉴权拦）
本机绑定（默认）      → 200（不受影响）
对外 + 没密码        → 进程退出码 2 + 说清原因
```

### ② 报价规则迁移 —— ✅ **查完发现不需要迁移**

**我原来担心**："没迁规则 ⇒ 每单走兜底报价 ⇒ 按成本卖、不赚钱"。

**查完结论**：`data/quote_rules.json` 确实不存在，但
`load_rules()` 会回退到 `qr.seed_rules()`，而那 6 条种子规则里：
```
万达报价（V5）   weight=20   ← 最高，会先命中
良票报价（V5）   weight=19   ← 次之
```
**★ 我逐档比对过 V5 生产库（.shadow-data/business-settings.sqlite3）**：

| | basis | 档位数 | 逐档完全一致 |
|---|---|---|---|
| 万达报价（V5） | `fixed_per_ticket` = V5 的 `fixed_per_ticket` | 6 = 6 | ✅ |
| 良票报价（V5） | `estimated` = V5 的 `estimated` | 6 = 6 | ✅ |

（万达 6 档全是 `fixed_add_fen=100`；良票 6 档是
`adjustment_bps` = 1000/800/600/400/300/100 —— 和 V5 库一字不差。）

**⇒ 规则是对的、还带加价，不需要迁移。** 另外 4 条是兜底规则
（`万达系一口价` weight=6 已启用、`兜底全院线预估` weight=3 已启用），
它们只在"映射不到渠道规则"时才命中，属于设计内。

### ③ 凭证文件权限

```
data/liangpiao.json 里是【明文】的良票 app_secret + 模型 key
⇒ 上服务器后必须 chmod 600，属主是跑服务的用户
```

### ④ 我们还没有的"内嵌 UI"（**不影响替换，影响上架**）

自检文档里标着「⚠️ 未实现」的三条都是**插件内嵌页**（闲鱼黄主题、
authedFetch 握手、高度自适应）。**那三条是"上架到鱼麦多市场"的要求，
不是"替换后端"的要求。** 替换只需要后端能对接插件。
