### 1.2 ★ `showDate` 实测是 no-op（四种情况返回完全一样）

```
不发 showDate                        → 影片 15 部 / 场次 127 / 日期 [1014,1015,1016,1017]
showDate=2026-10-14（ISO，我们发的）   → 影片 15 部 / 场次 127 / 日期 [同上]
showDate=20261014（YYYYMMDD）         → 影片 15 部 / 场次 127 / 日期 [同上]
showDate=1999-01-01（明显没排片）      → 影片 15 部 / 场次 127 / 日期 [同上]
```
**⇒ 上游（万达）收到但不用。我们的注释早就写明了这点。**

**但它有副作用：`show_date` 在缓存键里 ⇒ 每个不同日期产生一条独立缓存项，
内容却完全相同 ⇒ 重复拉同一份数据。**

**★ 待你定**：
```
① 保留（符合接口签名，万一以后生效；代价是缓存重复）
② 去掉（少一份重复缓存；代价是万一上游某天开始生效，我们要再补回来）
★ 我倾向①保留 —— 签名里有这个参数，不算"编的"，而且去掉的好处很小
```

### 2.5 修法

```python
# application/store.py 新增
BRANDS_TTL_SECONDS = 24 * 3600

def brands_age_seconds() -> float | None: ...

def refresh_brands_if_stale(api) -> int:
    """院线名缓存过期就重新拉一次；返回拉到的个数（0 = 没拉/失败）。"""
    age = brands_age_seconds()
    if age is not None and age < BRANDS_TTL_SECONDS:
        return 0                       # ★ 新鲜就不拉，省一次外网调用
    if api is None:
        return 0
    try:
        return sync_brands_from_api(api)
    except Exception:
        return 0                       # ★ 静默 —— 规则页断网也得能开

# server.py /api/rules
try:
    store.refresh_brands_if_stale(get_service().flow.api)
except Exception:
    pass
return self._json(rules_payload())
```

**为什么把"过期判断"放这里而不是无条件同步**：规则页是 GET，可能被反复打开；
`brand/list` 是要签名的外网调用。无条件同步 = 每刷一次页面打一次良票。

**为什么失败静默**：规则页在没配凭证/断网时也必须能打开（`load_brands` 有兜底）。
为了刷新名称而让整个页面报错，是本末倒置。

**为什么 `api` 从 `get_service().flow.api` 取**：现成的实例，不新建客户端。
