## 一、什么是「摆设」

设置页上每个开关/输入框，背后只有两种可能：

**第一种：真的管用**
```
你改它 → 存下来 → 系统干活时会看这个值 → 行为真的变了
例：「报价记录有效时长」改成 60 → 报价卡真的 60 分钟才失效
```

**第二种：只存不用 —— 这就是"摆设"**
```
你改它 → 存下来 → 刷新后还是你改的值（看起来生效了）
        → 但系统干活时【从来不看这个值】→ 行为一点没变
```

**危害是骗人**：你以为关掉了某个功能，其实没有。
比"功能没做"更糟 —— 后者一眼就知道没有，前者让人误以为有。

### 你会立刻懂的例子

设置页里有一项 **「闲鱼改价 → 自动改价开关」**。

改价链上我逐行查过：**没有任何一行读它**。
⇒ 你把它关掉，系统照样自动改价。

## 三、★★★ 审计过程我错了四次（这段比结论重要）

```
第 1 次报 42 个
  ← 脚本把 web/config.js（设置页自己渲染表单）当成"有人读"。
    设置页当然会列出所有 key ⇒ 全被判成活的。
    实际报的是 21 活 / 42 死 —— 那个 42 恰好接近，但是巧合。

第 2 次报 47 个（写进注册表时）
  ← 注册表多标了 5 个。多标的原因是我换了判据，
    把 `ai.enabled`、`"required": ["reply"]`、文档字符串里的 "keyword"
    都当成了"有人在读设置"。

第 3 次报 62 个
  ← 临时脚本 `_mark_dead.py` 里正好列着那些 key，
    被 `rglob("*.py")` 扫进语料 ⇒ "有人在读"。

第 4 次报 58 个 ← 正确
  ← 并用【健全性检查】验证了判据：先拿 3 条已知答案
    （CONFIG.recognize_quote.quote_ttl_minutes 等）和 3 条已知假阳性
    （order_refund_notices 等）试判据，全对才敢出结论。
```

**★ 还有两个技术坑：**
```
① `(?<![\w.])` —— Python 把 `[\w.]` 当字符集合解析，报 bad character class。
   这个异常在 re.search 内部抛出，我没接住 ⇒ 每行都抛 ⇒ 全部判成"没人读"。
② 即使写成 `(?<!\w)(?<!\.)` 也不对：section 名前面【正好就是那个点】
   （`CONFIG` + `.` + `recognize_quote`）⇒ lookbehind 排掉点就永远不匹配。
   ★ 正确：`(?<!\w)section\s*\.\s*key\b` —— 只排单词字符，留着点。
```

**教训**：判"有没有人读"这类事，必须
① 先去看**实际的访问语法**（`cfg.<section>.<key>`）
② 再写判据
③ **给判据本身写测试**（那 6 条健全性检查）
我这次是倒着做的，所以错了四次。

## 四、改了什么

**标记，不删除。** 理由：
```
删了 → 以后想接上去要重写【字段 + 界面 + 保存白名单】三处
标记 → 接上去时把注册表里那一行删掉即可
而且删掉之后运营会以为"本来就没这功能"，
不如显式写着"未接线"，让人知道这是【已知的未完成】。
```

### 1. settings.py 加一张注册表

```python
UNWIRED: dict[str, dict[str, str]] = {
    "fish_reprice": {
        "auto_reprice": "改价链刚接通，链路上还没读这些开关",
        ...
    },
    ...
}
```
**每个条目都写原因** —— 只写"未接线"，三个月后就分不清
"没来得及做"和"故意不做"；写了原因，接手的人才知道该不该接。

★ 做成**一张注册表 + 自动标记**，不是逐个字段手改：
手改要碰 21 个 dataclass、58 处，容易漏也难复查。

### 2. 设置页渲染（后端 `layout()` 带出 → 前端显示）

![设置页的未接线标记](img/unwired.png)

```
置灰 + 橙色「未接线」角标 + 角标悬停显示原因 + 行下写一行原因
区块头也显示「5 项未接线」，整块是死的时一眼能看出来
```

**设计取舍（为什么不是一律 disabled）**：
```
· 开关/单选/多选/排序：一点就变 ⇒ 【真的禁用】
  （不挡住的话，用户会以为改成功了 —— 而这正是要消灭的东西）
· 文本/数字：置灰但保留可选中，方便复制当前值（准备接线时要看）
· 排序列表：连拖动把手和序号徽标一起藏掉。
  拖不动却显示把手 = 界面在撒谎，和"改了没生效"是同一类问题。
```

### 3. ★★★ 一条防"摆设再长出来"的断言

```
不变量：不在 UNWIRED 里的控件，必须真的有人读它的值。
⇒ 以后新增一个"存了没人读"的字段，断言会失败。
```

这是整件事里最有价值的一条 —— 标记只是治了现状，断言才防住未来。

## 五、顺手查的一件更危险的事（结论：没问题）

`message` 这个 key 在 8 个区块里都出现（放映时间限制话术 / 夜间识别话术 /
催促下单话术 / 订单拦截话术 / 观影提醒话术 / 催收货话术 / 催好评话术…），
`enabled` 出现 6 次，`mode` 2 次。

**如果设置是扁平存的，改「催收货话术」会把「催好评话术」也改掉。**
查了 —— **按 section 嵌套存的**（`raw["催收货"]["message"]`），不冲突 ✓。
