# 接线：店铺级「自动发送」开关

> 日期：2026-10-14
> 店主原话：**「启用怎么没有关闭　这里设置为开关　关闭则不会自动发送信息」**
> 以及：**「这里删除吧　没啥用」**（指页面上那段"能做什么、不能做什么"的说明）

---

## 一、先说清一个容易混的地方

页面上原来那列「平台启用」是**只读徽标**，它显示的是**鱼麦多那边**的状态。
店主想要的"关闭"是**我们自己的开关**。**两者不是一回事：**

| | 谁的状态 | 能不能改 | 改了会怎样 |
|---|---|---|---|
| **平台启用** | 鱼麦多的 | **不能** | 官方只给了「读店铺列表」一个能力，没有增删改 |
| **自动发送**（新） | **我们自己的** | 能 | 关掉 ⇒ **不往这个店发任何自动消息** |

**★ 所以我没有把「平台启用」那列变成开关** —— 那会假装能改平台状态，
而且改不了（后端会失败或更糟：界面显示改了、平台没变）。

**做法**：加**单独一列**「自动发送」，列头下面写小字「我们是否发消息」，
把那列和平台状态明确分开。

---

## 二、关掉之后到底停什么

```
停：报价卡、AI 回复、取票码、发货通知、付款后回复……
    —— 一切【对买家发言】的自动消息

不停：内部记账命令（text 为空、extra.internal_only）
      —— 关掉开关不该让我们的排查也瞎掉
      不停：CLOSE_FAILED_ORDER 之类的止损动作
      —— 关的是"说话"，不是"止损"（错价单该关还是要关）
```

**★ 这个区分很重要**：如果连止损一起停，店主为了"别再自动回复"
而关掉开关，结果错价单不再自动关闭 —— 那是把一个小诉求搞成大事故。

---

## 三、改了什么

### ① 存储：`data/shops.json`（新文件）

```json
{ "2313315754": { "send_enabled": false } }
```
`application/store.py` 加三个函数：
```
load_shop_prefs()       读全部
save_shop_prefs(d)      写全部
shop_send_enabled(sid)  单店判断
```
**★ 默认 True**（没配过 = 开）：
- 保持原行为 —— 新增一个店铺就"默认静音"会让人完全找不到原因
- **配置读不到也返回 True**：配置故障时静默静音全部店铺，
  比"多发了消息"严重得多

### ② 后端闸门：`application/plugin_runtime.py`

```python
_shop_allows_send(ident)   # 单店判断（读不到配置 ⇒ True）
```
**加在【产生命令处】，不是插件执行时：**
```
· _from_buyer_message：买家回复 / AI 回复 → 开关关了就不排 SEND_MESSAGE
· _from_order_paid    ：三处（金额不符通知、付款后回复、兜底提示）
                        ★ 统一收口过滤，不逐处加判断
```
**★ 为什么在产生处拦**：在插件执行时拦只能拦住"发出去"，
命令还是会一条条排进队列、一条条判失败 —— 队列里堆一堆必然失败的
SEND_MESSAGE，出问题时根本看不出"是这个店的开关关了"。

**★ 为什么在 `_from_order_paid` 用"统一收口"而不是三处各写一遍**：
漏一处的后果是**关掉开关后买家仍然收到消息，而界面看起来是生效的**。

### ③ 接口：`GET/PUT /api/shops`

```
GET  ：店铺列表里每个店多一个 send_enabled（与平台状态分开两个字段）
PUT  ：{shop_id, send_enabled} ⇒ 只改我们自己的开关
       缺 shop_id / 缺 send_enabled ⇒ 400（不是 500，也不是静默成功）
       返回里带 scope 说明：「只影响我们是否往这个店自动发消息，
                            不改鱼麦多那边的店铺启用状态」
```

### ④ 界面：`web/shops.js` + `web/shops.html`

- 新增一列「自动发送」，用**全站同一个开关**（`style.css` 的 `.switch`）
  —— 不另造样式，视觉一致
- 点一下 → PUT → **以后端返回的值为准**（不靠本地状态猜）
- **失败要还原勾选**：不还原的话界面显示"已关"、实际没存上，
  是最容易骗人的一种不一致
- 删掉那段说明（店主说没用）：`<b>不能</b>：新建 / 改名 / 停用店铺…`

## 五、★ 顺带修的一条"失效的断言"

原来有一条断言靠**页面里有『不能…新建…鱼麦多后台』那段文字**
来保证"不假装能改平台状态"。店主删了文字后它失败了。

**我没有直接删掉它**（那条约束本身还该守），而是改成用**行为**守：
```
① 页面上没有任何"改平台"的控件（新建店铺/新增店铺/改名/停用店铺/删除店铺）
② 唯一可写的是我们自己的「自动发送」开关
③ 那个开关明确标着「我们是否发消息」（与平台状态分开）
```
**★ 教训**：靠"某段文案存在"来守约束是脆的 ——
文案是给人看的，会变；约束该用**控件在不在、点了会怎样**来守。
