## 二、★★★ 这次踩的最大的坑：密钥取错了文件

**症状**：切换后插件每秒报
```
pending command drain failed RECOVERY_INSPECTION_FAILED
```
而**我们这边一个请求都收不到**，日志 0 行。

**根因**（查了很多轮才对上）：
```bash
# 插件的 systemd 单元【按顺序】加载两个 EnvironmentFile：
EnvironmentFile=/etc/ticket-system-v5/plugin.env                  # SECRET = ce1f3e1e…
EnvironmentFile=/etc/ticket-system-v5/qr-shipment-credentials.env # SECRET = 6591…
                                                                    ↑ ★ 后者覆盖前者
```
**插件实际用的是第二个文件里的密钥**，而我从**第一个**文件取的。
⇒ 插件用 A 签名、我们用 B 验签 ⇒ **401** ⇒ 插件只说
`RECOVERY_INSPECTION_FAILED`，**完全看不出是密钥问题**。

**修**：`ticket-agent.env` 的密钥改从 `qr-shipment-credentials.env` 取。
修完两边哈希一致（`1a9938660510`），插件立刻恢复正常。

### ★ 这个坑教我的事

```
① 同名的 EnvironmentFile 有多个时，后面的会【静默覆盖】前面的。
   我看了第一个文件就下结论，没看第二个 —— 而 systemd 的实际行为
   只体现在【进程的环境变量】里。
   ⇒ 判据应该是"进程实际拿到了什么"，不是"文件里写了什么"。
   （我最后就是用 /proc/<pid>/environ 对哈希才对上的。）

② 401 和"没收到请求"这两种现象，我一开始分不清：
   插件端说失败，我这边日志 0 行 ⇒ 我以为是"没发出来"。
   实际是发出来了、被 401 拒了，而我们的日志【只记成功路径】。
   ⇒ 我补了插件端点请求日志（在验签【之后】打）——
     这掩盖了失败请求。正确的做法是验签失败也要能看到。

③ 排查过程中我自己造了两次假象：
   · 第一次：探测脚本里 sudo 没把环境变量传进去 ⇒ 报"secret 长度 0"
   · 第二次：systemd 把 stdout 重定向到文件 ⇒ journal 里看不到我们的 print，
     我误判成"没收到请求"
   ⇒ 假象和真问题长得一样，必须交叉验证（文件 + journal + /proc + 对拍）
```

## 三、切换步骤（实际执行的）

```bash
# ① 上传代码（排除运行时数据）
tar -czf /tmp/ticket-agent.tgz --exclude=./data --exclude=./__pycache__ \
    --exclude=./docs --exclude=./demos --exclude=./_demo \
    --exclude=./yumaiduo/plugin-runtime/node_modules .
scp /tmp/ticket-agent.tgz ubuntu@<host>:/tmp/
ssh <host> "mkdir -p ~/ticket-agent.new && tar -xzf /tmp/ticket-agent.tgz -C ~/ticket-agent.new && mkdir -p ~/ticket-agent.new/data"

# ② 建环境文件（★ 密钥从【第二个】EnvironmentFile 取！）
#    /home/ubuntu/ticket-agent.env  (600)
#    TICKET_AGENT_HOST=127.0.0.1
#    TICKET_AGENT_PORT=8801
#    YUMAIDUO_WEBHOOK_SECRET=<qr-shipment-credentials.env 里那把>
#    YUMAIDUO_TENANT_ID=107

# ③ 装 systemd 服务
#    /etc/systemd/system/ticket-agent.service
#    User=ubuntu / WorkingDirectory=~/ticket-agent.new
#    EnvironmentFile=/home/ubuntu/ticket-agent.env
#    ExecStart=/usr/bin/python3 server.py
#    Restart=always
sudo systemctl daemon-reload && sudo systemctl enable --now ticket-agent

# ④ 备份插件的 env（回滚要用）
sudo cp /etc/ticket-system-v5/plugin.env \
        /etc/ticket-system-v5/plugin.env.bak-before-ticket-agent

# ⑤ 切换：把插件的大脑指向我们
sudo sed -i 's|^V5_BACKEND_URL=.*|V5_BACKEND_URL=http://127.0.0.1:8801|' \
     /etc/ticket-system-v5/plugin.env
sudo systemctl restart ticket-system-v5-plugin
```

## 六、一句话总结

插件只报一句没有信息量的 `RECOVERY_INSPECTION_FAILED`，
而所有表象（我们日志 0 行）都指向"请求没发出来"——实际是发出来被 401 拒了。
判据只能是"进程实际拿到了什么"，不是"文件里写了什么"。**
